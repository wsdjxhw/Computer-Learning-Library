# TreeMap 与比较器

## 学习目标

- 理解 TreeMap 的定位：按 key 排序的 Map，红黑树底层，O(log n)。
- 掌握导航方法（firstKey/ceilingKey/floorKey…）与范围视图（subMap/headMap/tailMap）。
- 分清 Comparable（自然排序）与 Comparator（定制排序）的分工与写法。
- 知道 TreeMap 的两条红线：没有比较器会 ClassCastException、键禁止 null。

**前置知识**：[HashMap](../HashMap/知识详解.md)（哈希定位——对照组）、[Lambda与Stream](../../语言基础/Lambda与Stream/知识详解.md)（Comparator.comparing 的函数式写法）、[二叉搜索树](../../../../数据结构与算法/数据结构/二叉搜索树/知识详解.md)（红黑树的前身）。
**适用范围**：排行榜、区间查询、有序遍历、带权重的调度（如延时任务按时间取最近）。

---

## 一、本节解决什么问题

HashMap 查得快但"没大没小"：给一把键，它答不出"最小的？""比 80 大的第一个？""60 到 90 之间有哪些？"——hash 只管定位，不管大小关系。TreeMap 把条目装进**红黑树**（自平衡二叉搜索树），键的**大小顺序**成为一级公民：遍历天然有序、最值/前驱后继/区间查询都是 O(log n) 级。代价：put/get 从 O(1) 变 O(log n)，且键必须**可比较**——本篇的另一半主角 Comparator 就是解决"拿什么比"的。

## 二、核心原理

### 2.1 红黑树：会自己保持平衡的二叉搜索树

[二叉搜索树](../../../../数据结构与算法/数据结构/二叉搜索树/知识详解.md)的痛点：按序插入会退化成链表（O(n)）。红黑树靠五条性质（节点红/黑着色、根黑、红不相邻、任一节点到叶子的黑高相同等）配合**变色+旋转**，保证最长路径不超过最短的 2 倍——增删查稳定 O(log n)。面试一般不要求背五性质，要求**说得出"自平衡 BST、O(log n)、变色旋转维持平衡"**这三个关键词。

### 2.2 排序规则的两套来源

| | Comparable | Comparator |
| --- | --- | --- |
| 位置 | 写在类里（`implements Comparable<T>`） | 类外独立存在，随用随传 |
| 方法 | `int compareTo(T o)` | `int compare(T a, T b)` |
| 语义 | 这个类型**天生**的顺序（自然排序） | 某次使用的**定制**顺序，可反转可组合 |
| 数量 | 每类只能有一个 | 想要几个要几个 |
| 适合 | 时间、编号、版本号这类有公认顺序的 | 业务排序（按价格/销量/评分…） |

返回值约定（两者相同）：**负数=前者排前面，0=相等，正数=后者排前面**。

Comparator 工厂方法（JDK 8+，配[方法引用](../../语言基础/Lambda与Stream/知识详解.md)极顺）：

```java
Comparator.comparing(Student::score)              // 按分数升序
Comparator.comparingInt(Student::score)           // 基本流版，免装箱
Comparator.comparing(Student::score).reversed()   // 降序
Comparator.comparing(Student::score).thenComparing(Student::name)  // 分数同再比姓名
```

### 2.3 导航方法与范围视图（TreeMap 的独门武器）

```java
firstKey()/lastKey()        // 最小 / 最大
ceilingKey(k)  floorKey(k)  // ≥k 的最小 / ≤k 的最大（天花板/地板）
higherKey(k)   lowerKey(k)  // 严格 >k 的最小 / 严格 <k 的最大
subMap(from, to)            // [from, to) 区间视图（含头不含尾）
headMap(k) / tailMap(k)     // <k 的前缀 / ≥k 的后缀
```

范围视图是**视图**不是拷贝：原 Map 变动，视图实时联动（示例第 4 段验证）；查询代价 O(log n + 结果数)。

### 2.4 两条红线

1. **必须能比较**：键类没实现 Comparable、构造时也没给 Comparator → 第一次 put 就 ClassCastException（红黑树要靠比较决定往左还是往右）。
2. **键禁 null**：null 没法和任何东西比大小（HashMap 的 null 键专属桶在这是无解的）。

另注意：**TreeMap 的"相等"以比较器为准**（compare 返回 0 即视为同一个键），equals/hashCode 在这里不起作用——与 HashSet 判等体系不同。

## 四、常见误区与边界条件

| 误区 | 纠正 |
| --- | --- |
| 键类没实现 Comparable 也没传 Comparator | put 抛 ClassCastException（示例第 5 段） |
| compareTo 用减法（a.score - b.score） | 大数相减可能溢出（int 最小值取反还是负）；永远用 Integer.compare/Long.compare |
| 认为 TreeMap 用 equals 判重 | 用 compareTo/compare==0 判重；equals 无关紧要（自定义类最好让两者一致，避免别处踩坑） |
| TreeMap 键放 null | NullPointerException（HashMap 允许，对照记忆） |
| 修改了已放入的键的字段（键参与排序） | 树不会重新排位——顺序错乱、查不到；键要不可变 |
| subMap 结果当快照用 | 是视图，原 Map 变它就变；要快照就 new TreeMap<>(subMap) 拷一份 |
| 拿 TreeMap 当高性能 Map 用 | put/get 是 O(log n)，比 HashMap 慢；没有排序/区间需求就别用 |

**排查思路**："put 抛 ClassCastException" → 键没比较器；"顺序不对/丢键" → compareTo 与 equals 语义不一致，或键被原地修改；"区间查询慢" → 检查是不是把整棵树遍历后自己过滤（应该用 subMap）。

## 五、八股追问

**Q1（必考）：TreeMap 的底层是什么？put/get 复杂度？**
红黑树（自平衡二叉搜索树），增删查均 O(log n)。靠变色与左右旋转维持"最长路径 ≤ 2×最短路径"，避免 BST 按序插入退化成链表。**追问：TreeSet 和它什么关系？** TreeSet 底层就是 TreeMap（元素当 key、value 占位）——同 HashSet 之于 HashMap 的关系。

**Q2（必考）：TreeMap 和 HashMap 怎么选？**
HashMap：O(1) 查、无序、键要正确 hashCode（允许一个 null 键）。TreeMap：O(log n)、有序遍历、导航/范围查询、键要可比较（禁 null）。只要排序/区间/最值任一需求 → TreeMap；纯键值存取 → HashMap。
**追问：有没有又快又有序的？** 跳表——ConcurrentSkipListMap（并发有序 Map），O(log n) 且无锁化程度更高，见[并发容器篇](../ConcurrentHashMap与并发容器/知识详解.md)选型表。

**Q3（必考）：Comparable 和 Comparator 的区别？**
Comparable 写在类内部、定义自然排序、一类一份（compareTo）；Comparator 类外独立、一次一份、可组合可反转（compare）。类比：Comparable 是"身份证上的出生日期"，Comparator 是"今天想按什么排"。
**追问：同时存在时听谁的？** 构造 TreeMap 时传的 Comparator 优先——自然排序沦为没传时的默认。

**Q4（高频）：compareTo 返回值的语义？为什么不能用减法实现？**
负=排前、0=相等、正=排后。减法在极端值下溢出：`Integer.MIN_VALUE - 1` 溢出为正数，排序就错了；浮点还有 NaN 陷阱。**永远写 `Integer.compare(a, b)` / `Double.compare(a, b)`**。**追问：0 意味着什么？** 在 TreeMap 里 compare==0 视为同一个键——新 put 会覆盖旧值；"只比较了部分字段"的 Comparator 会把本不同的对象判重，一坑。

**Q5：TreeMap 有哪些导航能力？说个实际应用。**
firstKey/lastKey/ceilingKey/floorKey/higherKey/lowerKey + subMap/headMap/tailMap 范围视图，全部 O(log n) 级。应用：排行榜取前 N（headMap）、延时任务取最近到期（firstKey）、日志/监控按时间段拉取（subMap）、限流器按时间窗清理过期记录（headMap(now).clear()）。

**Q6：TreeMap 的键为什么不能是 null？HashMap 为什么可以？**
比较"null 和谁大"没有定义，put(null) 无所适从。HashMap 靠 hashCode 定位，null 键被特殊处理（hash 记 0）进固定桶——定位机制不依赖"比较"，所以可以。

**Q7（高频连线）：红黑树和 AVL 树、B+ 树的区别？**
红黑树：近似平衡（最长≤2×最短），增删旋转次数少，写多场景友好——TreeMap、HashMap 树化桶、epoll 都用它。AVL：严格平衡，查询更快、插入删除旋转更多——读极多写极少才划算。B/B+ 树：多路平衡、矮胖、节点对齐磁盘块——数据库索引的选型（MySQL InnoDB）。回答时点出"严格度 vs 修改成本"的取舍即可。

**Q8：subMap 返回的 Map 改动会影响原 TreeMap 吗？**
会——subMap/headMap/tailMap 是原树的**视图**，双向联动（示例第 4 段演示了原 Map 加条目视图立刻可见）；在视图上 put 也必须落在区间内，否则 IllegalArgumentException。

## 六、实际应用与取舍

- **排行榜/TopN**：分数做键、ID 做 value，firstKey/headMap 直接取。
- **时间轴/调度**：TreeMap<触发时间, 任务>，firstKey 永远是最近该执行的。
- **区间定价/路由**：金额区间→费率，floorKey 找到"不超当前金额的最大档位"。
- **有序去重输出**：TreeSet 一行搞定（如统计出现过的所有不重复 URL 并按序输出）。
- **取舍**：没有顺序需求别为"高级"付 O(log n) 的税；高并发有序场景上 ConcurrentSkipListMap。
