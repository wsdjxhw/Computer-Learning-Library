# HashMap

- 掌握 HashMap 的增删改查与三种遍历方式。
- 理解"同键覆盖"、null 键、返回值（put/remove 返回旧值）等行为。
- 会用 `getOrDefault` / `putIfAbsent` / `merge`，完成词频统计这类经典任务。
- 分清 HashMap / LinkedHashMap / TreeMap 的选型。

**前置知识**：[泛型](../../语言基础/泛型/知识详解.md)（`Map<K,V>`）；[哈希表底层原理](../../../../数据结构与算法/数据结构/哈希表/知识详解.md)（推荐先读，本篇不重复讲原理）。
**适用范围**：Java 集合框架；工程中与 ArrayList 并列的最常用容器。

## 一、HashMap 是什么

HashMap 是**基于哈希表实现的键值容器**：键经哈希函数定位到桶，平均 O(1) 完成按键存取。哈希冲突、负载因子扩容、键为什么必须不可变等**原理**在[数据结构与算法/哈希表](../../../../数据结构与算法/数据结构/哈希表/知识详解.md)有完整讲解（含手写实现），本篇聚焦 Java 的**用法、行为与选型**。

## 二、核心机制速览（详见数据结构篇）

| 要点 | HashMap 中的体现 |
| --- | --- |
| 桶 + 哈希函数 | `hash(key) ^ (hash >>> 16)` 打散后定位桶，扰动函数减少低位碰撞 |
| 冲突处理 | 桶内链表；链长 ≥ 8 且表长 ≥ 64 时树化（红黑树，最坏 O(log n)） |
| 负载因子扩容 | 默认 0.75，超过即容量翻倍 + rehash |
| 键需可哈希/不可变 | 自定义类做键必须同时重写 `hashCode` 和 `equals` |

## 三、示例代码逐段讲解

示例文件：`示例代码.java`（与下述段落编号一一对应）

**第 1 段：基本操作与同键覆盖**。put/get/containsKey/remove/size；两个关键行为——`get` 不存在的键**返回 null 而不是抛异常**；同键再 put 是**覆盖**且返回被覆盖的旧值（`put("Alice", 95)` 返回 90）。

**第 2 段：三种遍历**。`entrySet`（最常用：一次拿到键值，不要再 get 一次）、`keySet`（只要键时）、`values`（只要值时，示例顺手求和）。

**第 3 段：实用方法与词频统计**。

```java
map.getOrDefault("橙子", 0);        // 不存在给默认值，替代 containsKey+get 两步
map.putIfAbsent("橙子", 0);         // 没有才放，实现"无则初始化"
map.merge(word, 1, Integer::sum);   // 词频统计核心：有则旧值+1，无则置 1
```

词频统计（数每个单词出现几次）是 HashMap 最经典的应用，`merge` 一行等价于传统的 `if/get/put` 三行，且只查一次表。

**第 4 段：null 键与顺序**。HashMap 允许**至多一个** null 键（`m.get(null)` 正常工作）；**遍历顺序不保证**——示例中 {first, second, third} 打印成 {third, first, second}，且会随扩容变化。需要顺序用 LinkedHashMap（插入序）或 TreeMap（按键排序）。

## 四、常见误区与边界条件

| 误区 | 纠正 |
| --- | --- |
| 自定义类做键不重写 hashCode/equals | 默认按对象身份——内容相同的两个键各存一份，再也查不到；**必须成对重写** |
| 键用可变对象 | 存入后修改参与 hashCode 的字段 → 键"失踪"（原理见[哈希表篇](../../../../数据结构与算法/数据结构/哈希表/知识详解.md)可哈希性一节） |
| 依赖遍历顺序 | HashMap 无序；要插入序/排序换 LinkedHashMap/TreeMap |
| 用 `get(key) == null` 判断"不存在" | 值本身可能是 null；判存在用 `containsKey` |
| 遍历时增删 | ConcurrentModificationException（同 ArrayList） |
| 多线程共用 | 非线程安全；并发读多写少用 `ConcurrentHashMap` |
| 大量对象做键忘了-null | 自定义 equals 前先判 null 与 instanceof（IDE 生成即可） |

**排查思路**："明明存了却取不到" → 检查键类的 hashCode/equals 是否成对重写、键是否在存入后被修改；"值时有时无" → 疑似同键覆盖，用 put 的返回值打印旧值排查。

## 五、八股追问

HashMap 是 Java 面试的"压轴常客"，题号密度全场最高；哈希表通用原理见[数据结构/哈希表](../../../../数据结构与算法/数据结构/哈希表/知识详解.md)，这里聚焦 Java 实现的高频问答。

**Q1（必考）：HashMap 的底层结构？put 的大致流程？**
JDK 8 起是**数组 + 链表 + 红黑树**：put 先算 hash 定位桶 → 桶空直接放 → 桶冲突尾插链表 → 链长达到 8 且表长 ≥ 64 则树化（否则先扩容）；树节点缩到 6 退化回链表。

**Q2：为什么容量必须是 2 的幂？**
定位桶用 `(n - 1) & hash` 代替 `hash % n`：n 为 2 的幂时两者等价，而位运算远快于除法取模。还有第二重好处：扩容翻倍后，每个元素的新位置**要么在原下标、要么在原下标 + oldCap**——只看 hash 多出来的那一位就能分流，迁移干净利落。

**Q3：扰动函数 `(h ^ (h >>> 16))` 干什么用？**
把 hashCode 的**高 16 位异或进低 16 位**。因为定位桶只用低位（n-1 通常不足 16 位），不扰动的话两个"高位不同、低位相同"的 key 必然碰撞——扰动让高位信息也参与定位，代价只是一次移位加一次异或。

**Q4：为什么负载因子是 0.75？树化阈值为什么是 8？**
0.75 是空间利用率与冲突率的折中。阈值 8 来自**泊松分布**：负载因子 0.75 时，一个桶链长达到 8 的概率约 0.00000006——正常散列几乎不会发生，所以树化只是哈希质量极差时的兜底，不是常规路径；退化阈值取 6（留 2 的缓冲）防止在 8 附近反复树化/退化抖动。
**追问：链长到 8 一定树化吗？** 不一定——表长不足 64 时优先扩容（搬出新散布可能就打散了）。

**Q5（必考）：为什么重写 equals 必须同时重写 hashCode？**
HashMap 查找是"先 hashCode 定桶、再 equals 比对"两步。只重写 equals：内容相同的两个键散到不同的桶，**存进去就取不回**；只重写 hashCode：进了同一个桶，equals 判不相等，还是取不到。
**追问：为什么 String 适合做键？** 不可变（存入后 hash 不会失效）+ hashCode 缓存（见[字符串篇](../../语言基础/字符串/知识详解.md)）。

**Q6：JDK 7 头插和 JDK 8 尾插的区别？**
JDK 7 扩容时头插法在**并发扩容**下会让链表成环，get 时死循环；JDK 8 改尾插消除成环。但 HashMap 依然不是线程安全（并发 put 丢数据），并发场景用 `ConcurrentHashMap`。

**Q7：HashMap / Hashtable / ConcurrentHashMap 怎么比？**
HashMap 非同步、允许一个 null 键和 null 值；Hashtable 全方法 synchronized、不允许 null，属于历史遗留；ConcurrentHashMap 并发安全且吞吐高（JDK 8 起用 CAS + 锁单个桶，锁粒度极细）。

## 六、实际应用与取舍

- **键值缓存/索引**：ID → 对象、配置表、枚举名 → 枚举值。
- **计数与分组**：词频、用户行为统计（`groupingBy` 底层就是 map 合并）。
- **判重**：`HashSet` 本质就是只有键的 HashMap（原理同[数据结构/哈希表](../../../../数据结构与算法/数据结构/哈希表/知识详解.md)）。
- **选型口诀**：要快用 HashMap，要插入序用 LinkedHashMap，要按键排序/范围查询用 TreeMap（底层红黑树，原理见[二叉搜索树](../../../../数据结构与算法/数据结构/二叉搜索树/知识详解.md)的平衡树一节）。
- 需要有序遍历且写多读少时，LinkedHashMap 比反复 sort 一个 List 更划算。
