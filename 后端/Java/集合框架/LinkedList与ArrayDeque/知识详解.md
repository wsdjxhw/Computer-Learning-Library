# LinkedList 与 ArrayDeque

## 学习目标

- 建立正确认知：LinkedList 的价值不在"List"，而在它实现的 Deque（双端队列）。
- 用实测对比理解两头操作 O(1) 与随机访问 O(n) 的两面性。
- 掌握队列（FIFO）与栈（LIFO）的 Deque 标准写法，告别 Stack 类。
- 知道 ArrayDeque 为什么是官方推荐的队列/栈实现。

**前置知识**：[ArrayList](../ArrayList/知识详解.md)（数组实现的对照组）、[链表](../../../../数据结构与算法/数据结构/链表/知识详解.md)、[队列](../../../../数据结构与算法/数据结构/队列/知识详解.md)（数据结构视角）。
**适用范围**：任务队列、括号匹配/撤销栈、滑动窗口两头增删、BFS。

## 一、本节解决什么问题

"ArrayList 和 LinkedList 怎么选"是面试第一梯队的题，而多数人的答案是错的——背了"链表增删快"却不知道快在哪一头、慢在哪一头。真相：LinkedList 是**双向链表**，它同时实现了 List 和 Deque 两个接口；当 List 用时随机访问 O(n) 溃败，当**队列/栈**用才是主场。而即便在主场，JDK 官方也更推荐 **ArrayDeque**（循环数组双端队列）——本篇把这条完整的选型链讲透。

## 二、核心原理

### 2.1 LinkedList 的双面身份

```java
List<String>  a = new LinkedList<>();   // 面孔一：List（有序可下标——但下标很慢）
Deque<String> b = new LinkedList<>();   // 面孔二：双端队列（两头增删 O(1)——链表天赋）
```

内部是双向链表：每个节点存元素 + prev/next 两个引用。**两头**操作只改边界节点的指针 → O(1)；中间插入删除虽然"只改指针"，但**先要走到那个位置**（get/遍历 O(n)）——所以"链表中间插入快"是有条件的：你手里得先有那个节点（比如迭代器正停在那）。

随机访问的内部实现：按 `size >> 1` 判断离哪头近，从近的一头数过去——两头快、中间慢，仍是 O(n)。

### 2.2 Deque 的两副面孔：队列与栈

| 用途 | 进 | 出 | 看一眼 |
| --- | --- | --- | --- |
| 队列 FIFO | `offer(e)` 队尾进 | `poll()` 队头出 | `peek()` |
| 栈 LIFO | `push(e)` 压队头 | `pop()` 弹队头 | `peek()` |

推荐用 **Deque 接口**声明变量（`Deque<String> stack = new ArrayDeque<>()`）——接口表达意图，实现随时可换。**Stack 类不要再用**：继承 Vector、全方法 synchronized（没有必要的锁开销），是历史遗留。

### 2.3 ArrayDeque：循环数组

底层一个可扩容的 Object 数组，逻辑上首尾相接成环：头指针左移（减 1 取模）就是队头，尾指针右移就是队尾。两头操作 O(1) 均摊（偶尔扩容复制）。相比 LinkedList 的优势：

1. **连续内存**：CPU 缓存行友好；链表节点散落堆各处，每跳一次都可能缓存失效；
2. **无节点对象开销**：链表每个元素多 2 个引用 + 对象头，内存翻倍还增加 GC 压力。

限制：**不允许 null**——`poll()` 空队列返回 null 是专用信号，存进去就分不清"取到 null"和"队列空了"。

### 2.4 完整选型链

```text
按下标随机访问 / 尾部增删为主   → ArrayList
队列 / 栈 / 两头增删            → ArrayDeque（默认）
又要下标又要频繁两头增删（罕见）→ LinkedList
已废弃                         → Stack、Vector
```

## 四、常见误区与边界条件

| 误区 | 纠正 |
| --- | --- |
| 背"LinkedList 增删快"就到处用它 | 快仅限两头或已持有节点；中间增删要先 O(n) 走过去 |
| 用 for 循环下标遍历 LinkedList | 每次 get 都从头/尾数——O(n²) 的经典事故；用迭代器或 for-each |
| new Stack() 当栈 | 继承 Vector 全方法同步；Deque（ArrayDeque）是官方替代 |
| ArrayDeque 里放 null | 抛 NPE；null 被留作 poll 失败的信号 |
| 用 add/remove 语义不清的方法操作队列 | 用 offer/poll/peek（失败返回特殊值）；add/remove 失败抛异常 |
| poll/peek 返回 null 不判空 | 空队列返回 null 是正常语义，不是错误；先判或改用 element（抛异常版） |
| 认为 ArrayList 头插"也就是慢一点" | 头插是 O(n)，n 大时是数量级的慢（示例第 2 段） |

**排查思路**："遍历大链表巨慢" → 是不是下标 for 循环；"队列取到 null 崩了" → 没判空，或混用了 null 元素；"内存占用异常高" → 链表节点开销（每元素 ~2 个引用 + 对象头）。

## 五、八股追问

**Q1（必考第一梯队）：ArrayList 和 LinkedList 的区别？**
五维度：底层（动态数组 vs 双向链表）；随机访问（O(1) vs O(n)）；中间/头部插入（要挪元素 O(n) vs 改指针 O(1)，但先要走过去）；内存（连续紧凑 vs 每元素多 prev/next 引用且不缓存友好）；定位（ArrayList 是纯 List；LinkedList 还实现了 Deque，能当队列栈用）。
**追问：那日常用哪个？** 几乎总是 ArrayList——随机访问强、尾部增删均摊 O(1)、缓存友好；实测中即便头插场景，n 不大时 ArrayList 的 arraycopy（native）也常赢 LinkedList。

**Q2（高频）：LinkedList 可以当队列和栈用吗？分别怎么写？**
可以，它实现了 Deque。队列：offer 入尾、poll 出头；栈：push 压头、pop 弹头。**追问：为什么不用 Stack 类？** 继承 Vector（全方法 synchronized 的性能税），设计陈旧；官方文档自己推荐 Deque 替代。

**Q3：ArrayDeque 和 LinkedList 谁更适合当队列/栈？**
默认 ArrayDeque：循环数组、连续内存缓存友好、无节点对象开销，官方 Javadoc 明说"用作栈时可能比 Stack 快，用作队列时可能比 LinkedList 快"。LinkedList 仅在需要 null 元素（Deque 禁 null）或要在迭代中频繁用 listIterator 前后插删时考虑。
**追问：ArrayDeque 为什么禁 null？** poll/peek 空时用 null 表示"没有"，元素若是 null 语义就撞车了。

**Q4（高频）：ArrayList 头部插入为什么慢？LinkedList 两头为什么快？**
ArrayList 头插要把现有元素整体后移（System.arraycopy，O(n)）；LinkedList 头部增删只改 first 指针与相邻节点的 prev/next（O(1)）。但注意 ArrayList 的**尾部** add 是均摊 O(1)——最常见的循环 add 尾部它并不慢。

**Q5：LinkedList.get(i) 是怎么实现的？为什么说它两头快中间慢？**
先 `(i < size>>1)` 判断目标在前半还是后半，从更近的一头沿链走。头尾附近 O(1)，正中间 O(n/2)。**追问：所以 for(i) 循环 get 遍历 LinkedList 的复杂度？** O(n²)——必须用迭代器/for-each（沿链一次走完 O(n)）。

**Q6：RandomAccess 接口是干什么的？**
标记接口（无方法）。ArrayList 实现了它，LinkedList 没有——它向算法提示"我支持高效随机访问"，`Collections.binarySearch` 等会据此选择下标版或迭代器版实现。是"标记能力影响算法策略"的典型设计。

**Q7：为什么说链表"缓存不友好"？**
数组元素连续存放，读一个会把整块缓存行带进 CPU 缓存，后面的元素白捡；链表节点散落堆中，每次 next 跳转都可能是一次缓存缺失/内存访问。现代 CPU 访问内存比执行指令慢一两个数量级——这是 ArrayDeque 实测常胜 LinkedList 的底层原因。

## 六、实际应用与取舍

- **任务/消息队列（单机内存版）**：`Deque<Task> = new ArrayDeque()`，offer/poll；要阻塞等待换 [BlockingQueue](../../并发编程/并发工具类/知识详解.md)。
- **括号匹配/表达式求值/撤销重做**：ArrayDeque 当栈（push/pop）。
- **滑动窗口（两头进出的最值问题）**：ArrayDeque 两头 O(1) 是标配。
- **BFS 层序遍历**：ArrayDeque 当队列。
- **取舍**：写代码先问"我需要下标吗？"——不需要再问"是先进先出还是后进先出？"；两问都"否"才是 ArrayList 的纯粹场景。
