# ArrayList

## 学习目标

- 掌握 ArrayList 的增删改查与三种遍历方式。
- 踩过并记住 `remove(int)` / `remove(Object)` 的重载陷阱。
- 分清 `ArrayList`、`List.of`、`Arrays.asList` 三种列表的可变性。
- 了解 ArrayList 与数组的取舍、扩容原理的位置。

**前置知识**：[泛型](../../语言基础/泛型/知识详解.md)（`List<String>` 的语法）；[数组底层原理](../../../../数据结构与算法/数据结构/数组/知识详解.md)（推荐先读，本篇不重复讲原理）。
**适用范围**：Java 集合框架；日常开发出场率最高的容器。

## 一、ArrayList 是什么

ArrayList 是**基于动态数组实现的列表**：底层一个 `Object[]`，对外提供"可变长度、按泛型约束元素类型"的容器。它的行为完全由数组决定——**按下标访问 O(1)，中间插入/删除 O(n)**，容量不足时自动扩容（1.5 倍）。这些机制的完整讲解在[数据结构与算法/数组](../../../../数据结构与算法/数据结构/数组/知识详解.md)，本篇聚焦 Java 的**用法与陷阱**。

## 二、核心原理速览（详见数据结构篇）

| 操作 | 方法 | 复杂度 | 原因 |
| --- | --- | --- | --- |
| 按下标访问 | `get(i)` | O(1) | 数组寻址公式 |
| 尾部追加 | `add(e)` | 均摊 O(1) | 偶尔触发 1.5 倍扩容搬迁 |
| 中间插入/删除 | `add(i,e)` / `remove(i)` | O(n) | 后半段整体搬移 |
| 按值查找 | `indexOf` / `contains` | O(n) | 逐个 equals 比对 |

选型直觉：**读多写少、按下标访问 → ArrayList**；频繁头尾增删 → `ArrayDeque`/`LinkedList`（但绝大多数场景 ArrayList 仍是首选，缓存友好）。

## 三、示例代码逐段讲解

示例文件：`示例代码.java`（与下述段落编号一一对应）

**第 1 段：基本操作**。`add` 尾部追加、`add(1, "葡萄")` 指定下标插入（O(n)）、`get`/`set`/`size`/`indexOf`/`contains`——每个调用都标注了复杂度。

**第 2 段：remove 重载陷阱（本篇最重要）**。

```java
List<Integer> nums = List.of(10, 20, 30) 的可变副本;
nums.remove(1);                    // int 字面量 → 匹配 remove(int)：删【下标 1】→ [10, 30]
nums.remove(Integer.valueOf(1));   // Integer 对象 → 匹配 remove(Object)：删【值为 1】的元素
```

想按值删除 Integer 列表的元素却写 `remove(1)`，删掉的是下标 1——**高频线上 bug**。按值删必须包一层 `Integer.valueOf(...)`。

**第 3 段：遍历**。for-i（需要下标/改写时）、for-each（只读首选）；最后演示 for-each 中直接 `remove` 会抛 `ConcurrentModificationException`，安全做法是 `removeIf(...)`。

**第 4 段：排序**。`sort(Comparator.naturalOrder())` 升序、`reverseOrder()` 降序、`comparingInt(String::length).thenComparing(...)` 多级排序—— Comparator 组合是业务排序的常用手法。

**第 5 段：三种创建方式**。

| 创建方式 | 增删 | 改 set | 典型用途 |
| --- | --- | --- | --- |
| `new ArrayList<>()` | 可以 | 可以 | 默认选择 |
| `List.of(...)`（Java 9+） | 抛 UnsupportedOperationException | 抛 | 常量数据、不可变返回值 |
| `Arrays.asList(...)` | 抛（定长） | **可以** | 桥接数组与集合；注意它是原数组的视图 |

## 四、常见误区与边界条件

| 误区 | 纠正 |
| --- | --- |
| `list.remove(1)` 想按值删 | Integer 列表按值删要 `remove(Integer.valueOf(1))` |
| for-each 里 remove/add | ConcurrentModificationException；用 `removeIf` 或迭代器 |
| 越界访问 | `get(size())` 抛 IndexOutOfBoundsException，合法范围 `[0, size-1]` |
| 存基本类型 | 泛型只能 `List<Integer>`，自动装箱有开销、判等用 equals |
| 以为 `Arrays.asList` 是普通列表 | 定长 + 底层还是那个数组（修改互相可见） |
| 多线程共用 | ArrayList 非线程安全；并发用 `CopyOnWriteArrayList` 或 `Collections.synchronizedList` |
| 遍历时删除导致跳元素 | 与[数组篇](../../../../数据结构与算法/数据结构/数组/知识详解.md)同一坑：删除使后续元素前移 |

**排查思路**：IndexOutOfBounds 检查下标与 size 的关系；ConcurrentModificationException 搜索循环里的 remove/add；删除结果不对先看 remove 的重载。

## 五、八股追问

ArrayList 的八股集中在**扩容、选型、线程安全**三件事上，原理细节可回链数据结构篇。

**Q1（必考）：ArrayList 的扩容机制？**
无参构造时初始是**空数组**，首次 add 才分配容量 10；装满后扩 1.5 倍（`oldCap + (oldCap >> 1)`），由 `Arrays.copyOf` 整体搬迁。
**追问①：为什么是 1.5？** 在"扩容频率"与"空间浪费"之间折中——2 倍增长太快导致内存浪费，1.5 的均摊成本仍是 O(1)。
**追问②：怎么避免反复扩容？** 预知规模用 `new ArrayList<>(n)` 预分配。均摊分析的完整推导见[数据结构/数组](../../../../数据结构与算法/数据结构/数组/知识详解.md)。

**Q2：ArrayList 和 LinkedList 怎么选？**
绝大多数场景 ArrayList：随机访问 O(1)、内存连续对 CPU 缓存友好；LinkedList 只在"已持有节点位置的头尾频繁插删"占优。
**追问：LinkedList 中间插入是 O(1) 吗？** 插入动作本身 O(1)，但**定位到那个位置**要 O(n)——整体仍是 O(n)，这是"LinkedList 插入快"最常见的误读（链表原理见[数据结构/链表](../../../../数据结构与算法/数据结构/链表/知识详解.md)）。

**Q3：ArrayList 线程安全吗？替代方案？**
不安全。按场景选：读多写少、遍历时允许并发修改 → `CopyOnWriteArrayList`（写时复制出新数组）；要简单全局同步 → `Collections.synchronizedList`；队列场景用并发队列（`ConcurrentLinkedQueue`/`BlockingQueue`）。
**追问：Vector 为什么淘汰？** 全方法 synchronized，锁粒度太粗性能差；且方法级同步防不住"先 get 后 set"这类复合操作的竞态——加锁也未必安全。

**Q4：fail-fast 是什么？ConcurrentModificationException 怎么来的？**
迭代器持有创建时的 modCount，每次 next 先核对——发现列表被结构性修改（add/remove）立即抛 CME。注意：**单线程遍历中改动同样触发**，这不是并发专属异常。安全姿势：迭代器的 remove()，或 `removeIf(...)`。
**为什么这样设计？** 及早暴露修改冲突，而不是默默遍历出错乱的结果。

**Q5：`Arrays.asList` 和 `List.of` 各有什么坑？**
`Arrays.asList` 是**定长视图**：增删抛 UnsupportedOperationException，但 set 可以、且改动直接写回原数组（互相可见）；`List.of` 完全不可变、且拒绝 null 元素。
**追问：想要独立可变列表？** `new ArrayList<>(Arrays.asList(...))` 得到与数组脱钩的副本。

**Q6：ArrayList 为什么实现 RandomAccess？**
它是**标记接口**（无方法），声明"本实现按下标访问是 O(1)"，通用算法据此选策略——`Collections.binarySearch` 对 RandomAccess 类型用下标二分，否则退化为迭代器遍历。写性能敏感的通用代码时同样可用 `instanceof RandomAccess` 决定 for-i 还是迭代器。

## 六、实际应用与取舍

- 默认的顺序容器：数据列表、DTO 集合、分页结果。
- 需要频繁按下标随机访问的场景（它相对 LinkedList 的最大优势）。
- **不适合**：频繁头部插入删除（O(n) 搬移）、需要键值查找（用 [HashMap](../HashMap/知识详解.md)）、去重（`HashSet`）。
- 预知规模时 `new ArrayList<>(10000)` 预分配容量，避免反复扩容。
