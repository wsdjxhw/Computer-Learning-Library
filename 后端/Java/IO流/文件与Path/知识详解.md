# 文件与Path

## 学习目标

- 了解 `File` 老类的痛点，理解 NIO 为什么取代它。
- 掌握 `Path` 的路径运算（normalize/resolve/relativize/toAbsolutePath）。
- 掌握 `Files` 工具类：读写、复制、删除、列目录。
- 会用 `Files.walk` 遍历与递归清理目录树。

**前置知识**：[字节流与字符流](../字节流与字符流/知识详解.md)（Files 底层就是流的封装）、[异常处理](../../语言基础/异常处理/知识详解.md)。
**适用范围**：NIO 文件操作（Java 7+）；日常文件处理的现代标准 API。

---

## 一、本节解决什么问题

`java.io.File` 从 Java 1.0 用到今天，毛病一箩筐：方法失败**只返回 boolean 不给原因**（是没权限还是不存在？猜）、元数据 API 匮乏、跨平台行为不一致。Java 7 的 NIO 用两个类重新划分职责——**`Path` 只表达路径**（纯字符串语义运算），**`Files` 承载一切操作**（增删改查、属性、遍历，失败抛带原因的异常）。新代码的默认选择。

## 二、核心原理

### 2.1 Path：路径的语义化

Path 本身不代表文件存在，只是"路径的运算对象"：

| 方法 | 作用 | 示例 |
| --- | --- | --- |
| `normalize()` | 消除 `.` 和 `..` | `data\..\logs\a.log` → `logs\a.log` |
| `resolve(子路径)` | 向下拼接 | `D:\study` + `notes/a.txt` |
| `relativize(目标)` | 算相对路径 | walk 输出相对路径就用它 |
| `toAbsolutePath()` | 转绝对路径 | 基准是 **user.dir**（启动 java 时所在的目录） |

**相对路径的基准是 user.dir 而不是 .java 文件所在目录**——"明明在同一目录却说文件不存在"多半是基准搞错了。

### 2.2 Files：操作全集（失败抛异常）

读小文件 `readString`/写 `writeString`（显式传 charset，别赌默认值）；`copy(from, to, REPLACE_EXISTING)`；`delete`（目录非空抛 DirectoryNotEmptyException）；`createDirectories` 一口气建多级；`Files.list(dir)` 列一层目录、`Files.walk(dir)` 遍历整棵树——后两个**返回 Stream 且持有目录句柄，必须关闭**，否则 Windows 下连目录都删不掉（示例开发时真实踩到）。

### 2.3 walk 与递归清理

`Files.walk` 深度优先吐出整棵树的 Stream，配合 filter/map 就是声明式的目录扫描。**递归删除要倒序**（`sorted(reverseOrder())`）：先删最深的文件、再删空的目录——正序删到目录时它还有孩子，必然失败。

## 四、常见误区与边界条件

| 误区 | 纠正 |
| --- | --- |
| `Files.list/walk/lines` 的 Stream 不关闭 | 持有目录/文件句柄；Windows 下目录删不掉、句柄泄漏，必须 try-with-resources |
| 删除目录忘了先清空 | `delete` 对非空目录抛 DirectoryNotEmptyException；递归删除要**倒序** walk |
| 相对路径基准想当然 | 基准是 user.dir（进程启动目录），不是 class 文件/java 文件所在目录 |
| `copy` 目标已存在 | 默认抛异常；要覆盖传 `StandardCopyOption.REPLACE_EXISTING` |
| 读写不指定编码 | `Files.readString` 默认 UTF-8，与文件实际编码不符照样乱码 |
| `readString/readAllBytes` 读大文件 | 全量进内存；大文件用 `newBufferedReader` 逐行或流式处理 |
| Path.equals 大小写 | Windows 文件系统大小写不敏感，比较语义按平台来；严格比较用 `Files.isSameFile` |

**排查思路**："文件不存在"但肉眼可见 → 打印 `toAbsolutePath()` 对基准；删目录失败 → 查是否有未关闭的 list/walk Stream、是否倒序删除；NoSuchFileException 与 AccessDeniedException 是不同的失败原因（File 老类就给不了这个信息）。

## 五、八股追问

### Q1（必考）：File 和 NIO 的 Path/Files 有什么区别？为什么要换？

File 的三大硬伤：**失败只返回 boolean**（mkdir 失败不知道是权限还是路径不存在）、**功能残缺**（没有复制/移动、属性获取弱、不支持符号链接语义）、**跨平台行为不一**。NIO 拆成"Path 管路径表达、Files 管操作"，失败抛**带原因的具体异常**（NoSuchFile/AccessDenied/DirectoryNotEmpty），还带来 walk 目录树、文件属性、watch 服务等能力。

### Q2：Files.lines 和 readAllLines 有什么区别？

`readAllLines`：一次读入全部行，装进 `List<String>` 返回，文件关闭——小文件方便。`Files.lines`：返回**惰性 Stream**，逐行按需读，文件句柄挂在 Stream 上，**必须由使用者关闭**（try-with-resources）——大文件/流式处理的正解。

### Q3：Files.walk 遍历目录树要注意什么？

① 返回的 Stream 占着目录句柄，要关闭；② 遍历顺序不保证（要稳定输出自己 sorted）；③ 默认**不跟随符号链接**（防成环），传 FOLLOW_LINKS 选项时要防循环；④ 遍历中修改目录结构行为未定义，遍历与修改分开做。

### Q4：怎么安全地递归删除一个目录？

walk 出全树 → `sorted(Comparator.reverseOrder())` 倒序 → 逐个 delete：先删文件后删目录，任何一步失败都能捕获具体异常决定重试或上报。（JDK 21 仍没有官方一行 API，Guava/Apache 有实现；理解倒序原理比记 API 重要。）

### Q5：相对路径到底相对于谁？

**user.dir**——JVM 启动时所在的目录（`System.getProperty("user.dir")`）。IDE 里跑是项目根目录，命令行里跑是敲命令的目录。工程代码读资源应该用 classpath（`getResourceAsStream`）而不是文件系统相对路径，部署后文件系统里根本没有那些文件。

### Q6：什么是文件句柄泄漏？后果是什么？

打开文件/目录后不关闭，OS 侧的句柄一直被占用：Windows 上表现为"文件被另一进程占用，无法删除"；Linux 上 inode 无法回收，长期运行的服务句柄耗尽（Too many open files）直接瘫痪。try-with-resources 是根治手段。

## 六、实际应用与取舍

- **小文件读写**：`Files.readString/writeString` 一行；批量小文件操作避免频繁开关，考虑缓冲。
- **日志扫描/代码统计**：`walk + filter + lines` 组合拳（示例第 4 段的放大版）。
- **上传/导出**：临时文件用 `createTempFile` + `deleteOnExit` 兜底。
- **取舍**：要流式/增量/断点续传用经典流（[字节流与字符流](../字节流与字符流/知识详解.md)）；一次性操作 Files 更直接。框架内资源走 classpath 而非文件路径。

## 七、可继续学习的方向

- WatchService：目录变更监听。
- 文件属性与权限：`Files.readAttributes`、POSIX 权限。
- 内存映射文件（MappedByteBuffer）：大文件随机访问的高速通道。
- [线程池](../../并发编程/线程池/知识详解.md)：文件扫描 + 线程池 = 并行处理大批文件的常用架构。
