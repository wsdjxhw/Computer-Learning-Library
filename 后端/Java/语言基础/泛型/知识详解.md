# 泛型

## 学习目标

- 理解泛型解决的核心问题：把类型检查从运行期提前到编译期。
- 会写泛型类、泛型方法，理解类型边界 `<T extends ...>`。
- 理解通配符 `? extends` / `? super` 与 PECS 原则。
- 理解类型擦除及其限制。

**前置知识**：[数据类型与变量](../数据类型与变量/知识详解.md)（包装类）、[ArrayList](../../集合框架/ArrayList/知识详解.md)（泛型的最大受益者）。
**适用范围**：Java 语言核心；集合框架与几乎所有框架 API 的语法基础。

---

## 一、本节解决什么问题

没有泛型的集合只能装 `Object`：什么都塞得进，取出来要强转，类型错误拖到**运行期**才以 ClassCastException 爆炸。泛型让你在写代码时声明"这个容器/方法处理什么类型"，编译器替你把关——**错误从运行期挪到了编译期**。

```java
List<Object> oldStyle = new ArrayList<>();  // 无类型约束：能装字符串也能装整数
(String) oldStyle.get(1);                  // 运行时 ClassCastException！

List<String> safe = new ArrayList<>();
safe.add(42);                              // 直接编译报错，当场抓住
```

Java 5 之前集合连这层约束都没有（只能按"原始类型"声明，即裸写 `List` 不带参数）。今天直接写原始类型会触发 unchecked 编译警告——警告本身就在说"你在绕过类型检查"。

## 二、核心原理

### 2.1 泛型类：类型作参数

```java
class Box<T> {          // T 是类型参数，像"类型的占位符"
    private T value;
    public void set(T value) { this.value = value; }
    public T get() { return value; }
}

Box<String> nameBox = new Box<>();   // 使用时才确定 T 是什么
```

写一次 Box，String/Integer/任意类型通用——**类型安全的代码复用**。注意：泛型参数不能是基本类型（`Box<int>` 非法），要用包装类 `Box<Integer>`。

### 2.2 泛型方法与类型边界

```java
static <T> T first(List<T> list) { return list.get(0); }         // <T> 声明在返回类型前，类型由参数推断

static <T extends Comparable<T>> T max(List<T> list) { ... }     // 边界：T 必须"可比较"
```

没有边界时编译器只知道 T 是"某个类型"，什么方法都不能调；`<T extends Comparable<T>>` 收窄后，方法体内才能用 `compareTo`。

### 2.3 通配符与 PECS

背景坑：`List<Integer>` **不是** `List<Number>` 的子类型（尽管 Integer 是 Number 的子类）——否则你就能把 Double 塞进"以为是 List<Integer> 的引用"。通配符用来表达**更宽松的参数类型**：

```java
double sum(List<? extends Number> list)   // 读：Number 的任意子类都收 —— 只读
void fill(List<? super Integer> list)     // 写：能装 Integer 的任意列表 —— 可写
```

记忆口诀 **PECS**（Producer Extends, Consumer Super）：参数是**生产者**（往外给数据，只读）用 `? extends`；是**消费者**（往里收数据，只写）用 `? super`。`? extends` 的列表编译器禁止 `add`（不知道具体类型，装错就破坏类型安全）。

### 2.4 类型擦除

泛型只活在**编译期**：编译后 `List<String>` 与 `List<Integer>` 是同一个 `List` 类，T 被擦成 Object（有边界时擦成边界类型）。示例直接验证：

```java
new ArrayList<String>().getClass() == new ArrayList<Integer>().getClass()   // true！
```

由此产生的限制：运行期拿不到 T 的真实类型、不能 `new T()` / `new T[]`、`List<String>` 与 `List<Integer>` 不能构成重载（擦除后签名相同）。（Kotlin/C# 的泛型是具化的，运行期可查——语言设计的对比点。）

## 四、常见误区与边界条件

| 误区 | 纠正 |
| --- | --- |
| 以为 `List<Integer>` 是 `List<Number>` 的子类型 | 泛型不变（invariant）；跨子类通配要 `? extends`/`? super` |
| 用基本类型做泛型参数 | `List<int>` 非法，用 `List<Integer>`（注意[装箱开销与缓存陷阱](../数据类型与变量/知识详解.md)） |
| 对 `? extends` 列表 add | 编译器禁止写入；要写用 `? super` |
| 运行期想拿到 T | 擦除后拿不到；传入 `Class<T>` 参数解决 |
| 泛型类静态成员用 T | 静态成员与实例的 T 无关，编译报错 |
| 忽略 unchecked 警告 | 警告几乎总是意味着类型安全漏洞，修到消失 |

**排查思路**：ClassCastException 的堆栈定位到强转处 → 检查该处的数据来源类型声明；"类型不兼容"编译错 → 先想 PECS 该用哪边。

## 五、八股追问

泛型的八股几乎全部围绕**类型擦除**展开——它是 Java 泛型一切"怪现象"的总根源。

**Q1（必考）：什么是类型擦除？Java 为什么这么设计？**
泛型只存在于编译期：编译后 T 被替换为边界类型（无边界即 Object），调用处由编译器自动插入强转。设计动机是**兼容**——Java 5 引入泛型时，不能让存量字节码失效，擦除是代价最小的方案；代价是运行期丢失泛型信息（对比 C#/Kotlin 的具化泛型，运行期可查）。
**追问：怎么证明？** `new ArrayList<String>().getClass() == new ArrayList<Integer>().getClass()` 为 true（见示例第 5 段）。

**Q2：运行期拿不到 T，需要时怎么办？**
显式传入**类型令牌** `Class<T>`（如 `EnumMap<K, V>(keyType)`、Jackson 的 `readValue(json, Class<T>)`）；更复杂的泛型场景用"超级类型令牌"（通过匿名子类保留签名）。

**Q3：为什么泛型参数不能是基本类型？**
擦除后形参是 Object，而 int 是值类型、不是 Object 的子类，放不进去——只能 `List<Integer>`，随之带来装箱开销与缓存陷阱（见[数据类型与变量](../数据类型与变量/知识详解.md)）。
**追问：以后会支持吗？** Project Valhalla 的"特化泛型"正在解决这件事。

**Q4：`List<Integer>` 是 `List<Number>` 的子类型吗？**
不是——Java 泛型是**不变（invariant）**的。假如是子类型，就能 `List<Number> ln = intList; ln.add(0.5);` 把 Double 塞进 Integer 列表，类型安全瞬间崩塌。需要跨子类读写时用通配符表达。
**追问：数组呢？** 数组是**协变**的：`Object[] o = new String[1]` 能编译，`o[0] = 42` 运行时才抛 ArrayStoreException——把类型检查拖回运行期，正是泛型不变要消灭的反面教材。

**Q5：PECS 是什么？为什么 extends 只读、super 可写？**
Producer Extends, Consumer Super：参数是生产者（往外给数据）用 `? extends`，是消费者（往里收数据）用 `? super`。
为什么：`List<? extends Number>` 不知道具体装哪个子类，写入任何东西都可能破坏类型安全，编译器干脆禁止 add；`List<? super Integer>` 至少确定"装得下 Integer"（Integer 放进 List\<Number\>/List\<Object\> 都安全），所以可写。

**Q6：能写 `f(List<String>)` 和 `f(List<Integer>)` 两个重载吗？**
不能——擦除后签名都是 `f(List)`，编译报 duplicate method。
**追问：桥方法是什么？** 子类实现泛型接口（或继承泛型父类）时，编译器为保持多态额外生成的合成方法，如在 `X implements Comparable<X>` 里，除 `compareTo(X)` 外还会生成转调的 `compareTo(Object)`。

## 六、实际应用与取舍

- **集合框架**：`List<E>`、`Map<K,V>` 全靠泛型——没有它就没有类型安全的容器。
- **框架 API**：Spring 的 `Repository<User, Long>`、MyBatis 的 `Mapper<T>`、RxJava/Reactor 的 `Flowable<T>`。
- **自己设计 API**：返回 `T` 而不是 Object，让调用方零强转；写工具方法时优先泛型方法而不是复制粘贴多个类型版本。
- **取舍**：泛型签名复杂到读不懂时（多级嵌套通配符），宁可拆成两个方法或放宽类型 + 文档说明。
