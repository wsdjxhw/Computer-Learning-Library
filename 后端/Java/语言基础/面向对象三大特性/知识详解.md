# 面向对象三大特性

## 学习目标

- 理解封装、继承、多态各自解决什么问题，不再把它们当背诵名词。
- 掌握 `private`/`protected`/`public`、`super`、`@Override` 的用法。
- 理解向上/向下转型、`instanceof` 与动态绑定。
- 分清方法重载（overload）与方法重写（override）。

**前置知识**：类与对象的基本概念（`class`、`new`、构造方法）；[数据类型与变量](../数据类型与变量/知识详解.md)。
**适用范围**：Java 语言核心；后续集合、框架、设计模式全部建立在这三个特性上。

---

## 一、三大特性各解决什么问题

| 特性 | 一句话 | 解决的问题 |
| --- | --- | --- |
| 封装 | 把数据和方法包进类，字段私有、方法把关 | 对象自己保护自己的合法性，外界无法绕过校验乱改状态 |
| 继承 | 子类自动获得父类的字段和方法 | 重复代码只写一次（is-a 关系） |
| 多态 | 父类引用调用方法，运行时按真实类型执行 | 新增子类不改调用方代码——扩展性的来源 |

## 二、核心原理

### 2.1 封装：字段私有 + 方法把关

```java
public void setAge(int age) {
    if (age < 0) {          // 唯一写入口拦截非法值
        return;             // 例：setAge(-1) 被拒绝，年龄仍是 3
    }
    this.age = age;         // this.age 是成员变量，age 是参数
}
```

直接 `dog.age = -1` 的写法在任何入口都能塞进脏数据；封装后所有修改必须过校验这一关。** Getter/setter 不是仪式，是海关。**

### 2.2 继承与重写

- `class Dog extends Animal`：Dog 复用 Animal 的非 private 成员；`super(name, age)` 构造父类部分，必须写在子类构造方法第一行。
- **方法重写（override）**：子类重新实现父类的同名同参方法；`@Override` 注解让编译器校验"确实重写了"，防手误写成重载。
- Java 类**单继承**（一个 `extends`），接口可多实现——详见[接口与抽象类](../接口与抽象类/知识详解.md)。

### 2.3 多态与动态绑定

```java
Animal[] zoo = { new Dog("旺财", 3), new Cat("咪咪", 2) };
for (Animal a : zoo) {
    System.out.println(a.makeSound());   // 汪汪 / 喵
}
```

同一个编译期调用 `a.makeSound()`，JVM 在**运行时**按对象的真实类型（Dog/Cat）选择执行版本——这就是**动态绑定**。它带来关键好处：以后新增 `Bird` 类，这段遍历代码一个字都不用改。**多态三要素**：继承（或接口实现）+ 重写 + 父类引用指向子类对象。

### 2.4 转型与 instanceof

```java
Animal maybeDog = new Dog("阿黄", 5);   // 向上转型：自动，安全（丢失子类特有方法的可见性）
if (maybeDog instanceof Dog d) {        // Java 16+ 模式匹配：判断+转型+绑定变量一步完成
    d.fetch();                          // 向下转型后才能调子类特有方法
}
```

### 2.5 重载 vs 重写（高频考点）

| | 重载 overload | 重写 override |
| --- | --- | --- |
| 位置 | 同一个类里 | 子类与父类之间 |
| 要求 | 方法名相同、**参数列表不同** | 方法名、参数、返回类型完全一致 |
| 绑定时机 | **编译期**按参数类型选择 | **运行期**按对象真实类型选择 |
| 示例 | `bark(int)` / `bark(String)` | Dog 重写 Animal 的 `makeSound()` |

## 四、常见误区与边界条件

| 误区 | 纠正 |
| --- | --- |
| 到处写 public 字段 | 字段 private，按需暴露 getter/setter 并校验 |
| 忘写 `@Override` | 注解能让编译器抓出"以为重写了其实签名不同"的 bug |
| 用继承复用一切 | 继承是 is-a；只是"想复用代码"应组合（has-a），滥用继承会造成层级僵化 |
| 向上转型后强转不判断 | 先 `instanceof` 再强转，否则 ClassCastException |
| 构造方法里调可重写方法 | 父类构造先于子类字段初始化执行，可能用到未初始化的状态 |
| 重写时缩小访问权限 | 只能保持或放大（public 不能改成 private） |

**排查思路**：调用到"错误版本"的方法 → 画继承图确认重写签名；强转报错 → 检查对象真实类型与 `instanceof`。

## 五、八股追问

OOP 是 Java 面试的地基题，考察方式多是"给场景讲区别"，死背名词过不了关。

**Q1（必考）：重载和重写的区别？**
重载：**同一个类**里方法名相同、参数列表不同，**编译期**按参数类型静态选择；重写：**子类**覆盖父类同名同参方法，**运行期**按对象真实类型动态绑定。
**追问①：重写的签名规则？**"两同两小一大"——方法名、参数相同；返回类型和受检异常范围 ≤ 父类；访问权限 ≥ 父类。
**追问②：只改返回类型能构成重载吗？** 不能，编译报错；返回类型不参与重载判定。

**Q2：多态的实现原理？**
每个类有一张**虚方法表（vtable）**，记录各虚方法实际执行的入口；`invokevirtual` 在运行期按对象的**真实类型**查表分派——这就是"父类引用调到子类实现"的底层机制。对照记忆：static 方法与字段走 `invokestatic`/`getstatic`，编译期按引用类型绑定，**没有多态**。

**Q3：继承下的初始化顺序？**
父类静态初始化 → 子类静态初始化 → 父类实例字段与构造块 → 父类构造方法 → 子类实例字段与构造块 → 子类构造方法。
**追问：super() 为什么必须写在第一行？** 子类初始化逻辑可能依赖父类的状态，父类部分必须先就绪。
**追问：构造方法能被重写吗？** 不能——构造方法不是虚方法（不参与动态绑定，方法名绑定类名），只能被重载。

**Q4：构造方法里调用可被子类重写的方法，有什么坑？**
父类构造先于子类字段初始化执行，而动态绑定在构造期间照样生效——此时调到的已是子类重写版本，它会读到**尚未初始化的子类字段**（null/0）。这是 Effective Java 明确列出的陷阱：构造器里只调 private/final 方法。

**Q5：static 方法能被重写吗？**
不能。子类写同名同参的 static 方法只是**隐藏（hiding）**：通过哪个引用调用就执行哪个版本，与对象真实类型无关。原因见 Q2——static 调用不经过 vtable。

**Q6（开放题）：为什么要封装/继承/多态？**
封装保护对象不变量、把校验收拢到唯一入口；继承消除重复并建立 is-a 可替换关系；多态让调用方不依赖具体实现——它是开闭原则和一切框架扩展点（重写钩子方法）的机制基础。
**追问：为什么说组合优于继承？** 继承让子类耦合父类实现细节、层级一旦定下很难改；组合关系可以运行时替换，故"为复用而继承"时应优先考虑组合。

## 六、实际应用与取舍

- **封装**：所有 JavaBean / entity / DTO 的字段私有 + getter/setter；Spring、MyBatis 等框架都基于此约定。
- **继承**：框架中的基类（如 `RuntimeException` 体系、`HttpServlet`）——你重写钩子方法，框架负责调用。
- **多态**：策略模式、模板方法、回调；集合框架 `List` 的 ArrayList/LinkedList 可互换也靠它。
- **取舍**："组合优于继承"是经验法则：能用 has-a 达成就不要 is-a。
