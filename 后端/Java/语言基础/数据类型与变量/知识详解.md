# 数据类型与变量

## 学习目标

- 记住八大基本类型及其位数、取值范围，理解"静态强类型"的含义。
- 理解整型溢出与浮点精度问题的根源，知道何时换 long / BigDecimal。
- 分清自动提升与强制转换，以及强制转换的丢数据风险。
- 掌握包装类、自动装箱/拆箱，以及 Integer 缓存导致的 `==` 陷阱。

**前置知识**：任何语言的基础变量概念；最好已看过[数据结构/数组](../../../../数据结构与算法/数据结构/数组/知识详解.md)（对比 Python 的动态类型更好理解）。
**适用范围**：Java 语言基础，JavaSE 必修第一课。

---

## 一、本节解决什么问题

Java 是**静态强类型**语言：每个变量声明时确定类型、终身不变，编译期就做类型检查。这换来两样东西——错误提前暴露、运行更高效。要理解 Java 的一切行为（为什么集合只能装对象、为什么有泛型），都要从"类型"这一课开始。

## 二、核心原理

### 2.1 八大基本类型（primitive types）

| 分类 | 类型 | 位数 | 范围 / 说明 | 默认值 |
| --- | --- | --- | --- | --- |
| 整型 | `byte` | 8 | -128 ~ 127 | 0 |
| | `short` | 16 | ±3.2 万 | 0 |
| | `int` | 32 | ±21 亿（整数默认） | 0 |
| | `long` | 64 | ±922 京（字面量加 `L`） | 0L |
| 浮点 | `float` | 32 | 约 6~7 位有效数字（加 `f`） | 0.0f |
| | `double` | 64 | 约 15 位（小数默认） | 0.0 |
| 字符 | `char` | 16 | 无符号，单个 UTF-16 字符 | '\u0000' |
| 布尔 | `boolean` | — | 只有 true / false | false |

基本类型**不是对象**：不能为 null、没有方法、不能放进集合——这是包装类和泛型那一课的起点。

### 2.2 溢出：里程表式绕回

整数在固定位数里按补码存储，超出上限不报错、直接绕到最小值（`Integer.MAX_VALUE + 1` 得 `-2147483648`）。最隐蔽的是**中间结果溢出**：`million * million / million` 期望 100 万、实际 -727，因为乘法中间值 10¹² 早已溢出——大数运算先把操作数转成 `long`。

### 2.3 浮点精度：二进制装不下十进制小数

`0.1 + 0.2 = 0.30000000000000004`。浮点数按 IEEE 754 二进制存储，0.1、0.2 这类十进制小数是二进制下的无限循环，必然舍入。因此：**浮点数永远不用 `==` 比较**（用容差 `Math.abs(a-b) < 1e-9`）；金额等精确计算用 `BigDecimal`（且用字符串构造 `new BigDecimal("0.1")`）。

### 2.4 类型转换

```text
自动提升（安全，自动完成）: byte → short → int → long → float → double
                          char ↗
强制转换（显式，可能丢数据）: 反方向必须写 (目标类型)
```

- 浮点转整型是**截断**不是四舍五入：`(int) 3.99 = 3`。
- `(byte) 128 = -128`：8 位装不下，高位截断后正好是 -128 的补码。
- `char` 本质是无符号 16 位整数，可与 `int` 互转。

### 2.5 包装类与 Integer 缓存

每种基本类型都有包装类（`int` → `Integer` 等）。Java 5 起自动装箱（`Integer a = 5`）走 `Integer.valueOf()`，它**缓存了 -128 ~ 127 的对象**：

```java
Integer a = 127, b = 127;  // 都取自缓存 → 同一对象 → a == b 为 true
Integer c = 128, d = 128;  // 超出缓存 → 两个新对象 → c == d 为 false
c.equals(d);               // true：equals 比较数值
```

这就是面试经典题"127 与 128"的完整答案。规则：**包装类型判等一律 `equals`**。

## 四、常见误区与边界条件

| 误区 | 纠正 |
| --- | --- |
| 用 `==` 比较包装类型 | 一律 `equals`；缓存范围外的 `==` 结果不可预测 |
| 以为整数除不尽会得小数 | `10 / 3 = 3`（int 除 int 还是 int），要小数先转 `10.0 / 3` |
| 浮点用 `==` 判等 | 用容差比较或 `BigDecimal` |
| long 字面量忘加 L / float 忘加 f | `long x = 9000000000;` 编译报错（超出 int 的字面量范围） |
| 拆箱不判空 | 数据库/集合中的 `Integer` 可能为 null，运算前先判 |
| 以为 char 是"一个字符"就够用 | 是 16 位**码元**，增补字符（如部分 emoji）需两个码元表示 |

**排查思路**：数值结果离谱（负数/跳变）先怀疑溢出；小数尾数不对是精度；`==` 时对时错查缓存。

## 五、八股追问

本主题是面试第一梯队的考点。先记结论，更要能讲出"为什么"——追问两轮就见真章。

**Q1：`Integer a = 127` 与 `Integer b = 128`，`==` 比较的结果分别是什么？为什么？**
127 是 true、128 是 false。自动装箱走 `Integer.valueOf()`，它缓存了 -128 ~ 127 的对象：范围内返回**同一对象**（`==` 为 true），范围外 `new` 新对象（`==` 为 false）。`==` 比较的是引用。
**追问**：缓存范围能改吗？→ 上限可用 `-XX:AutoBoxCacheMax=<n>` 调大，且只有 Integer 提供此参数；Byte/Short/Long 固定 -128~127。结论永远成立的那句话是：**包装类型判等一律 equals**。

**Q2：int 和 Integer 的区别？**
int 是基本类型：存值、不能为 null、无方法、默认 0；Integer 是引用对象：可为 null、有方法、默认 null。本质是"性能 vs 对象能力"的取舍——集合与泛型擦除后装的是 Object，值类型放不进去，所以**集合元素、可空字段（数据库 NULL、map.get 结果）必须用 Integer**。

**Q3：自动装箱/拆箱的本质是什么？**
编译器语法糖：装箱处插入 `valueOf()`，拆箱处插入 `intValue()` 等，JVM 指令层面并无"装箱"这回事。最大的坑有两个：对 null 拆箱抛 NPE（见第 4 段的 map.get 案例）；`Integer` 与 `int` 用 `==` 比较时会**自动拆箱**按数值比，混着引用比较时行为不一致——又一个只用 equals 的理由。

**Q4：为什么 `0.1 + 0.2 != 0.3`？BigDecimal 为什么必须用字符串构造？**
IEEE 754 用二进制存小数，0.1、0.2 是二进制无限循环，必然舍入。`new BigDecimal(0.1)` 接收的是已经丢精度的 double，误差原样带入；`new BigDecimal("0.1")` 或 `BigDecimal.valueOf(0.1)` 才精确。
**追问**：两个 BigDecimal 判等？→ `equals` 连精度（scale）一起比，`1.0` 不等于 `1.00`；比数值大小用 `compareTo`。

**Q5（经典编译题）：`short s = 1; s = s + 1;` 与 `s += 1;` 有何区别？**
前者**编译错误**：`s + 1` 中 s 自动提升为 int，int 赋回 short 必须显式强转。后者合法：复合赋值运算符自带隐式强转，等价于 `s = (short)(s + 1)`。

**Q6：switch 支持哪些类型？为什么 long 不行？**
byte/short/char/int 及其包装类、枚举（Java 5+）、String（Java 7+）。long 不行是因为 switch 底层的 tableswitch/lookupswitch 指令按 **int 索引**做表跳转，64 位值无法直接充当跳转表下标。

## 六、实际应用与取舍

- 日常计数、下标用 `int`；时间戳、大 ID、文件大小用 `long`；科学计算 `double`；金额 `BigDecimal`。
- 集合、泛型、可空字段用包装类型；纯计算、循环变量用基本类型（避免装箱开销）。
- 与其他语言对照：Python 的 int 无限精度、无类型声明——Java 的这套边界是"性能 + 严格"的设计取舍。
