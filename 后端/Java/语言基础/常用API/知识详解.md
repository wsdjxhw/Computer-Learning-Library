# 常用API

## 学习目标

- 掌握 Object 的 `equals`/`hashCode`/`toString` 重写约定，理解为什么必须成对重写。
- 会用 `Objects` 工具类写出更安全的判空与比较。
- 掌握 `java.time` 日期时间 API 与 `DateTimeFormatter`。
- 掌握 `BigDecimal` 的正确用法与两大陷阱（构造方式、equals 判等）。

**前置知识**：[数据类型与变量](../数据类型与变量/知识详解.md)（浮点精度问题）、[面向对象三大特性](../面向对象三大特性/知识详解.md)（重写）、[HashMap](../../集合框架/HashMap/知识详解.md)（hashCode 定位的场景）。
**适用范围**：Java 标准库中使用频率最高的一批"工具型" API，日常开发天天用。

---

## 一、本节解决什么问题

学完语言基础后，真实代码里大量时间其实花在几类"配套操作"上：对象怎么判等、日期怎么算、金额怎么算才不丢精度、工具类怎么少写判空。这些 API 分散在 `java.lang`、`java.util`、`java.time`、`java.math` 里，本篇把最常用的一批集中讲清——**每个都有正确姿势和经典陷阱**。

## 二、核心原理

### 2.1 Object：所有类的公共祖先

| 方法 | 作用 | 重写要点 |
| --- | --- | --- |
| `toString()` | 打印/日志展示 | 返回有意义的内容，如 `小明(18)` |
| `equals(Object)` | 内容判等 | 五约定：自反、对称、传递、一致、对 null 恒为 false |
| `hashCode()` | 哈希定位 | **与 equals 一致**：equals 相等 ⇒ hashCode 必须相同 |

hashCode 约定的反方向不要求（hash 相同可以不相等），但违反正方向会让 HashSet/HashMap 直接失灵——`HashSet` 去重先按 hashCode 找桶再按 equals 比对（见[HashMap](../../集合框架/HashMap/知识详解.md)），只重写 equals 的类，两个"相等"对象散在不同桶里，重复照样存进去。

### 2.2 Objects：null 安全工具

`Objects.equals(a, b)` 内部先判 null 再比较（两个 null 也相等）；`Objects.requireNonNull(x, "消息")` 把 NPE 提前到参数检查处；`Objects.hash(字段...)` 生成与字段一致的 hashCode。原则：**对可能是 null 的引用做比较，用 Objects 而不是自己写 if**。

### 2.3 java.time（Java 8+）：不可变日期时间

`LocalDate`（日期）/`LocalDateTime`（日期+时间）/`Duration`（时间量）/`Period`（日期差）。全部**不可变**：`plusDays` 等"修改"方法返回新对象、原对象不变——与 String 同一设计（线程安全的根源，对比老 `SimpleDateFormat` 的线程不安全）。格式化/解析用 `DateTimeFormatter`（也不可变、线程安全）。

### 2.4 BigDecimal：精确十进制

内部是任意精度整数 + 小数位数（scale），不存在二进制舍入误差。两条铁律：

1. **构造用字符串**（或 `BigDecimal.valueOf(double)`）：`new BigDecimal(0.1)` 会把 double 的误差原样带进来（示例输出里那串 55 位小数就是证据）。
2. **判等用 compareTo**：`equals` 连 scale（精度）一起比，`1.0` 不等于 `1.00`。

除法除不尽（如 1/3）必须指定 scale 和 `RoundingMode`，否则直接 `ArithmeticException`。

## 四、常见误区与边界条件

| 误区 | 纠正 |
| --- | --- |
| 只重写 equals 不重写 hashCode | HashSet/HashMap 里"存进去取不出、去重失效"；IDE 生成两个一起写 |
| `a.equals(b)` 时 a 可能为 null | 换 `Objects.equals(a, b)`，或保证非空 |
| `new BigDecimal(0.1)` | 用字符串构造或 `valueOf`；Double.toString 后构造 |
| BigDecimal 用 `equals` 比较 | 比数值用 `compareTo() == 0` |
| 除法不指定舍入 | `divide(除数, scale, RoundingMode.HALF_UP)` |
| 日期字段可变共享（老 Date/Calendar） | java.time 全不可变，放心共享 |
| 计时用 currentTimeMillis | 系统时钟可回拨；用 `nanoTime()`（且只算差值，绝对值无意义） |
| 以为 round 就是四舍五入 | round(-2.5) = -2，"四舍五入到最近整数，.5 向上（正无穷方向）" |

**排查思路**：HashSet 出现重复 / HashMap 取不到值 → 检查键类的 equals/hashCode；金额对不上分 → 找 `new BigDecimal(double)` 或 double 直接运算；日期"改了没变" → 不可变，要接返回值。

## 五、八股追问

本主题的八股集中在 **equals/hashCode 约定** 与 **BigDecimal**，两者都是"问一句就能探底"的题。

**Q1（必考）：重写 equals 为什么必须重写 hashCode？**
因为约定要求"equals 相等 ⇒ hashCode 相等"。反例推演：只重写 equals 的 Student 两个对象内容相等但（默认）hashCode 不同，HashSet 会把它们放进**不同的桶**，去重逻辑根本走不到 equals 那一步——重复元素就出现了。
**追问：反过来，只重写 hashCode 呢？** 同桶了，但 equals 按对象身份判不相等，还是判重失败。两个方法是一套协议的两个环节。

**Q2：equals 的五大约定是什么？为什么要守约？**
自反（x=x）、对称（x=y ⇔ y=x）、传递、一致（多次调用结果不变）、对 null 恒 false。不守约的后果直接落在集合上：比如不对称的 equals 会让 `list.contains(x)` 和 `set.contains(y)` 给出矛盾结果，HashMap 行为变得不可预测。

**Q3：`==`、`equals`、`hashCode` 三者的关系？**
`==` 比较基本类型值/引用地址；equals 默认就是 `==`（Object 的实现），重写后比内容；hashCode 是对象的散列指纹，**只服务哈希容器**，不用于判等。

**Q4：为什么 Java 8 要重造一套日期 API？**
老 `Date` 三宗罪：**可变**（setHours 能改状态，共享即事故）、**线程不安全**（`SimpleDateFormat` 格式化时共享内部 Calendar，并发出错乱日期）、API 反直觉（月份从 0 开始、年份从 1900 偏移）。java.time 全不可变 + 线程安全 + 语义清晰（LocalDate/LocalDateTime/ZonedDateTime 各司其职）。
**追问：Date 还在用怎么办？** 老代码用 `Instant` 互转桥接：`Date.from(instant)` / `date.toInstant()`。

**Q5：SimpleDateFormat 为什么线程不安全？**
`format()` 过程中会**修改**内部共享 Calendar 的状态，多线程并发调用互相覆盖。修法：方法内局部创建、ThreadLocal 包装，或直接换 `DateTimeFormatter`（不可变）。

**Q6：BigDecimal 有哪些必考陷阱？**
① double 构造带误差——用字符串构造；② `equals` 比 scale——`1.0 ≠ 1.00`，比大小用 `compareTo`；③ 除不尽必须给 `RoundingMode`，否则 ArithmeticException；④ 它也**不可变**——`x.add(y)` 返回新对象，必须接住返回值，`x.add(y)` 后丢弃返回值等于白算。

**Q7：Objects.requireNonNull 应用在什么场景？**
构造器/公共方法入口的参数校验：与其让 null 潜伏到第 50 行再 NPE，不如在入口处立刻抛出带清晰消息的 NPE（fail-fast）。`Optional.orElseThrow`、Spring 的 `Assert` 是同思路。

## 六、实际应用与取舍

- **实体类/DTO**：一律重写 equals/hashCode/toString（IDE 或 Lombok 的 `@EqualsAndHashCode`/`@ToString` 生成）。
- **金额、积分、费率**：全程 BigDecimal + 字符串构造 + 明确 RoundingMode；数据库对应 DECIMAL 类型。
- **日期**：新代码只用 java.time；传给老框架时用 `Instant` 互转。
- **取舍**：热循环里高频比较的场景，重写 equals 时把最可能不同的字段放前面短路。
