# 多线程基础

## 学习目标

- 掌握 Thread/Runnable 两种创建方式，理解 start 与 run 的本质区别。
- 理解竞态条件的成因，会用 synchronized 保护共享状态。
- 掌握 wait/notify 的协作模型（生产者-消费者）。
- 理解 volatile 的可见性语义与 interrupt 的中断约定。
- 认识线程的六种状态。

**前置知识**：[面向对象三大特性](../../语言基础/面向对象三大特性/知识详解.md)、[异常处理](../../语言基础/异常处理/知识详解.md)、[ArrayList](../../集合框架/ArrayList/知识详解.md)（它为什么线程不安全）。
**适用范围**：Java 并发的地基；后续线程池、JUC、Spring 并发处理全部建立在这些概念上。

## 一、本节解决什么问题

单线程程序同一时刻只做一件事；浏览器渲染时不能下载、服务器处理 A 的请求时 B 只能排队。多线程让 CPU 在多件事之间**快速切换**（并发）或真正同时执行（多核并行）。代价立刻出现：**多个线程操作同一份数据时结果不可预测**——这就是并发问题的根源，也是本篇两大主角（synchronized、wait/notify）要解决的。

## 二、核心原理

### 2.1 创建线程的两种方式

```java
new Thread() { public void run() {...} }.start();   // 继承 Thread：占用了继承名额
new Thread(() -> {...}, "名字").start();            // 实现 Runnable：推荐，任务与线程解耦
```

**start vs run 是必考点**：`start()` 向 JVM 申请新线程，由它调度执行 run()；直接调 `run()` 只是普通方法调用——在当前线程同步执行，多线程无从谈起。

### 2.2 竞态条件：counter++ 不是一步

`counter++` 编译后是**读 → 加 1 → 写回**三步。两个线程交错执行（A 读到 100，B 也读到 100，各加 1 写回 101）就丢了一次更新——示例实测 20 万次无锁累加只得到 12.7 万左右。`synchronized(锁对象)` 把代码块变成**原子区**：同一时刻只有一个线程能进入（互斥），共享状态的修改从此可预测。

synchronized 锁的是**对象**，不是代码——两个线程用同一个锁对象才能互斥；锁不同对象形同虚设。

### 2.3 wait/notify：线程间接力

```java
synchronized void put(int v) throws InterruptedException {
    while (槽满) wait();        // 释放锁、沉睡，等同伴 notify
    ...存入...
    notifyAll();                // 唤醒等着的同伴
}
```

三条约 定：① wait/notify **必须在 synchronized 块内**（持有锁才能操作监视器，否则 IllegalMonitorStateException）；② 等待条件用 **while 而不是 if**（醒来后重新检查条件，防"虚假唤醒"）；③ 多个等待者时用 `notifyAll`（notify 只随机叫醒一个，可能叫错人导致死锁）。

### 2.4 volatile：可见性，不是原子性

Java 内存模型允许每个线程把共享变量缓存在工作内存（CPU 缓存/寄存器）——一个线程改了 `running`，另一个可能永远看到旧值（示例第 4 段的循环停不下来就是这个病）。`volatile` 强制每次读写都走主内存，修改**立刻对其他线程可见**。

但 volatile **不保证原子性**：`volatile int c; c++` 照样丢更新（它只管可见，不管三步不被打断）。计数器要用 `AtomicInteger`（CAS）或加锁。

### 2.5 线程六态

```text
NEW --start()--> RUNNABLE（就绪+运行）
RUNNABLE --等锁--> BLOCKED          --拿到锁--> RUNNABLE
RUNNABLE --wait()/join()--> WAITING --notify/notifyAll/join结束--> RUNNABLE
RUNNABLE --sleep(n)/wait(n)/join(n)--> TIMED_WAITING --超时或唤醒--> RUNNABLE
RUNNABLE --run()结束--> TERMINATED（终态）
```

## 四、常见误区与边界条件

| 误区 | 纠正 |
| --- | --- |
| 调 run() 以为开了线程 | 只有 start() 开新线程；run() 是同步方法调用 |
| `synchronized` 锁住"代码" | 锁的是**对象**：实例方法锁 this、静态方法锁 Class 对象；两个线程锁不同对象不互斥 |
| wait 的条件判断用 if | 用 while——醒来后条件可能又被别人改掉了 |
| 以为 volatile 能替代锁 | 只保证可见性和有序性；`c++` 等复合操作仍需锁或 AtomicXXX |
| wait/notify 写在同步块外 | IllegalMonitorStateException |
| catch InterruptedException 后不管 | 惯例 `Thread.currentThread().interrupt()` 补回标记，让上层感知 |
| 停线程用 stop() | 已废弃：直接掐断会破坏数据一致性；用 interrupt + 状态位 |
| 共享 ArrayList/HashMap | 非线程安全（见[ArrayList 误区表](../../集合框架/ArrayList/知识详解.md)）；并发用 CopyOnWriteArrayList/ConcurrentHashMap |

**排查思路**："结果偶尔不对" → 竞态，找无保护的共享可变状态；"线程卡死不动" → jstack 看是 BLOCKED（等锁，查死锁）还是 WAITING（等 notify/Condition）；"改了标志位没反应" → 可见性问题，考虑 volatile。

## 五、八股追问

并发是面试的重头戏，基础篇就有大量高频题。

**Q1（必考）：start() 和 run() 的区别？**
start() 请求 JVM 启动新线程，run() 被调度执行；直接调 run() 是普通同步调用、不开线程。**追问：一个 Thread 对象能 start 两次吗？** 不能——终态后不能再 start，抛 IllegalThreadStateException；要再跑就 new 一个新 Thread。

**Q2（必考）：sleep 和 wait 的区别？**
四点：① 归属——sleep 是 Thread 的静态方法，wait 是 Object 的方法；② **锁**——sleep 抱着锁睡，wait 会**释放锁**；③ 唤醒——sleep 到点自动醒，wait 需要 notify/notifyAll（或超时版本到点）；④ 场景——sleep 是"我自己歇会"，wait 是"我等同伴干活"的线程协作。

**Q3：synchronized 锁的到底是什么？**
对象监视器（monitor）。三种用法对应三个锁对象：实例方法 → this；静态方法 → 类的 Class 对象；同步块 → 括号里指定的对象。**追问：两个线程分别访问同一对象的 synchronized 实例方法和普通方法？** 普通方法不加锁直接进——synchronized 只挡也加锁的人。

**Q4（高频）：volatile 的作用？能保证线程安全吗？**
两个语义：**可见性**（写立即刷主存、读强制拉主存）+ **有序性**（禁止指令重排）。**不保证原子性**——`count++`、`check-then-act` 这类复合操作照样出事。单写多读的标志位是它的标准用武之地（示例第 4 段），计数请用 AtomicInteger。

**Q5（经典）：双重检查锁（DCL）单例为什么需要 volatile？**
`instance = new Singleton()` 不是原子的：分配内存 → 初始化 → 赋引用三步可能被重排成"先赋引用后初始化"；另一线程在第一次非空检查时拿到**未初始化完的对象**直接使用就炸了。volatile 禁止这个重排。
**追问：还有别的单例写法吗？** 静态内部类（类加载机制保证只初始化一次）、枚举（天然防反射、防反序列化破坏）。

**Q6：怎么优雅地停止一个线程？**
stop() 已废弃（强掐破坏一致性）。正解看场景：任务里有阻塞调用（sleep/wait/IO）→ **interrupt()**，任务内响应 InterruptedException 收尾退出；纯轮询任务 → **volatile 状态位**；两者结合最稳。catch InterruptedException 后要把中断标记补回去（interrupt()），不能吞掉。

**Q7：线程有哪几种状态？BLOCKED 和 WAITING 的区别？**
NEW/RUNNABLE/BLOCKED/WAITING/TIMED_WAITING/TERMINATED 六态。BLOCKED 是**等锁**（进 synchronized 没抢到）；WAITING 是**主动等待同伴**（wait/join/park，无期限）；TIMED_WAITING 带超时（sleep(n)/wait(n)）。

**Q8：守护线程（daemon）是什么？**
服务型线程（如 GC）：`setDaemon(true)` 要在 start 前设置；**所有用户线程结束时 JVM 直接退出**，守护线程不等它跑完——所以守护线程里别写必须完成的收尾逻辑。

## 六、实际应用与取舍

- **IO 密集任务并行化**（批量下载、文件扫描）：多线程把等待时间重叠起来（配[线程池](../线程池/知识详解.md)食用）。
- **生产者-消费者**：读写缓冲解耦速率差异（日志异步写、消息队列的雏形；工程里用 BlockingQueue 免去手写 wait/notify）。
- **状态标志**：优雅停机（volatile running + interrupt）。
- **取舍**：共享可变状态越少并发越简单——优先"不可变对象 + 线程封闭（局部变量）"，必须共享时再上锁/原子类。
