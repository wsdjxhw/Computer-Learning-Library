### 6.（编程）"每个部门工资最高的员工"——写出两种解法：窗口函数版与相关子查询版。

### 8.（概念 + 猜输出）对 `learn_sql.emp` 执行：

```sql
SELECT job FROM emp WHERE deptno = 10 UNION     SELECT job FROM emp WHERE deptno = 20;  -- 记为 A

```

A、B 各返回几行？什么场景该用哪个？

<summary>参考答案（先自己做完再看）</summary>

### 1.

- 写在 **ON**：条件参与"配对"。配不上条件的右表行不出现，但**左表行照样保留**（右侧补 NULL）——左连接语义完整。
- 写在 **WHERE**：连接照常发生后再过滤最终结果。补出来的 NULL 行过不了比较（`NULL > x` 是 UNKNOWN），整行被删——**左连接退化成内连接**。
- 对照示例 2.1（ON，7 行）与 2.2（WHERE，6 行），差的正是部门 40 那一行。

### 2.

返回 **0 行（Empty set）**。子查询 `SELECT mgr FROM emp` 的结果集里含 NULL（KING 没有经理）。`x NOT IN (..., NULL)` 等价于 `x<>a AND ... AND x<>NULL`，只要与 NULL 比较就是 UNKNOWN，整个条件永远凑不出 TRUE，且**不报错**。

两种改法：

```sql
-- 写法一：NOT EXISTS（推荐，逐行判断存在性，与 NULL 无关）
SELECT e.ename FROM emp e
WHERE NOT EXISTS (SELECT 1 FROM emp m WHERE m.mgr = e.empno);

-- 写法二：先把 NULL 摘掉再 NOT IN
SELECT ename FROM emp
WHERE empno NOT IN (SELECT mgr FROM emp WHERE mgr IS NOT NULL);
```

两种写法都返回 8 人：SMITH、ALLEN、WARD、MARTIN、TURNER、ADAMS、JAMES、MILLER（KING 不在——他有下属）。

### 3.

**a=14，b=13，c=5**。COUNT(\*) 数所有行；COUNT(mgr) 跳过 KING 那行的 NULL；job 去重后是 CLERK/SALESMAN/MANAGER/ANALYST/PRESIDENT 共 5 种。

### 4.

依次是 **NULL、1、1、NULL**。`NULL = NULL` 和 `0 = NULL` 的结果都是 UNKNOWN（显示为 NULL）——所以"mgr = NULL 查不出 KING、NOT (0=NULL) 也查不出任何行"；判断 NULL 只能 `IS NULL`；`<=>` 是 NULL 安全等号。

### 5.

错在 SELECT 里的 `ename`：它既不在 GROUP BY 里，也不是聚合函数。按 deptno 分组后每组有多个人，"这组的 ename"没有唯一答案，老版本返回随机值，MySQL 5.7.5+ 默认的 `ONLY_FULL_GROUP_BY` 直接拒绝。

```sql
-- 改法一：明确要聚合信息（每组人数）
SELECT deptno, COUNT(*) AS 人数 FROM emp GROUP BY deptno;

-- 改法二：要"组内代表行"，用 ANY_VALUE() 显式声明"随便挑一个"（把含糊变成自觉）
SELECT deptno, ANY_VALUE(ename) AS 任意一名员工 FROM emp GROUP BY deptno;
```

要"每组最高工资那个人"不是 GROUP BY 的活，见第 6 题。

### 6.

```sql
-- 解法一：窗口函数（保住并列用 RANK；ROW_NUMBER 会把并列的第 1 名挤成第 2 名）
SELECT deptno, ename, sal
FROM (SELECT deptno, ename, sal,
             RANK() OVER (PARTITION BY deptno ORDER BY sal DESC) AS rk
      FROM emp) t
WHERE rk = 1
ORDER BY deptno;

-- 解法二：相关子查询（天然保住并列）
SELECT e.deptno, e.ename, e.sal
FROM emp e
WHERE e.sal = (SELECT MAX(sal) FROM emp WHERE deptno = e.deptno)
ORDER BY e.deptno;
```

`ROW_NUMBER()` 给并列的 SCOTT/FORD 硬排 1、2 名，`WHERE rn = 1` 只留 SCOTT——FORD 被丢掉。`RANK()` 给并列者同名次 1，两人都保留（这正是示例 3.3 与 4.4 的输出：4 行）。

### 7.

窗口函数带 `ORDER BY` 时的默认帧是 `RANGE BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW`。**RANGE 帧按"值"划界**：排序值相同（同一天）的行是"同位"，一起进出帧——所以两人的累计都是"包含两人之和"的 23625.00（19675 + 3000 + 950）。

逐行累计要显式改成 **ROWS** 帧：

```sql
SUM(sal) OVER (ORDER BY hiredate ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW)
```

ROWS 帧按物理行划界，先到的行先算（同一天谁先谁后仍取决于排序；要确定性给 ORDER BY 补第二列，如 `, empno`）。

### 8.

A 返回 **4** 行（MANAGER、PRESIDENT、CLERK、ANALYST——重复的 CLERK/MANAGER 被去掉）；B 返回 **8** 行（3 + 5 原样拼接）。
UNION 去重但有去重开销；**确定无重复（或业务就要保留重复）时用 UNION ALL**，省掉去重的排序/哈希成本。两查询列数必须相同、类型建议对齐。
