# 维护计算机学习库

把用户想学习的概念整理成结构清楚、可以独立学习、可以动手验证的主题资料。每个知识点的唯一学习载体是一个离线可开的**学习页**。

## 先理解现有结构

1. 阅读项目根目录的 `README.md`、`AGENTS.md` 和相关大类下已有目录。
2. 搜索是否已有相同或高度重叠的知识点，优先补充或重构现有内容，避免重复建档。
3. 保留用户已有内容和目录命名；除非用户明确要求，不做与当前主题无关的大规模迁移或改名。

## 先设计学习路径

1. 明确前置知识与 3–5 个可验收的学习目标，再确定正文结构；不要直接把资料堆进模板。
2. 找出核心难点，为每个难点安排合适的图示、互动或即时练习，确保学完后能预测、能判断或能写出。
3. 新建或重构页面前阅读 `references/学习页设计规范.md`；从 `assets/学习页模板.html` 复制基础体验组件，再按主题替换内容和互动，不保留模板占位文字。
4. 模板统一排版、导航、进度和存储等基础体验，不统一知识讲解的篇幅与形式。

## 确定存放位置

1. 根据知识点的核心用途选择最合适的大类，而不是仅凭出现的编程语言判断：
   - 服务端开发、数据库、分布式、服务端框架或中间件通常归入 `后端/`。
   - 浏览器、Web UI、客户端交互和前端框架通常归入 `前端/`。
   - 单片机、RTOS、驱动、硬件接口和嵌入式开发通常归入 `嵌入式/`。
2. 如果现有大类确实不合适，创建语义明确的新大类；不要把明显不相关的内容硬塞进现有目录。
3. 只有当两个或以上知识点共享一个稳定主题时，才在大类下建立中间分类，例如 `后端/数据库/`。若新主题预期将自然形成系列，也可以先建立中间分类，但要避免只有形式、没有聚合作用的层级。
4. 一个知识点使用一个名称清晰的独立目录。目录名优先采用学习者熟悉的中文术语，必要时保留标准英文名称或缩写。
5. 主题跨多个方向时，选择承担主要讲解的目录作为唯一正文位置；其他方向若确有需要，只放简短索引链接，避免复制两套内容。

## 知识点的交付形态

每个知识点目录包含两份核心交付物：

| 交付物 | 说明 |
| --- | --- |
| `学习页.html` | 唯一学习载体：知识解析、图示、互动演示、练习、延伸阅读集成一页 |
| 示例代码 | 可运行或可验证的真实代码（含面向学习者的详细注释）；多文件时放 `示例代码/` 目录并附 `README.md`（入口、命令、预期结果） |

旧形态四件套（`知识详解.md` + `互动演示.html` + `练习.md`）已退役，**不追溯**已建成的旧知识点（除非用户明确要求迁移）。

### 学习页.html 总体要求

1. 单文件自包含：双击即可在浏览器打开、离线可用；原生 HTML/CSS/JavaScript（ES5 风格优先），不依赖 CDN、构建工具或本地服务器。共享系列导航是允许的本地相对依赖，加载失败不得影响正文和练习。
2. 全中文界面；首屏明确「学什么、需要什么前置知识、怎样学、如何验证学会」，用简短指南代替大面积警告条。
3. 所有 `localStorage` 访问统一经过 try/catch 存储适配层，隐私模式下页面不崩、互动和练习仍可用。
4. 术语、结论、输出与 `示例代码/` 严格一致。
5. 正文默认不小于 `16px`，行高与行宽适合长读；标题层级清楚，重点结论、误区、真实报错和进阶内容有一致的视觉区分。
6. 桌面目录高亮当前章节，移动端提供等价可展开目录；360px 宽度无页面级横向溢出，宽表格独立滚动。
7. 阅读记录、演示操作与答题成绩分别呈现，不把答题数冒充整页进度；支持继续上次学习，分开重置阅读、成绩和代码草稿。
8. 提供可见焦点、表单可访问名称、动态结果文本、`scroll-margin-top`、减少动画和基本打印样式；颜色不是表达正误的唯一方式。

### 页面结构与讲解深度

典型骨架（按知识适配裁剪，不机械套模板）：主题引入与学习目标 → 多个核心章节（每章按「目标 → 讲解 → 图示/演示 → 即时检验 → 本章记住」形成闭环）→ 综合动手练习 → 闯关与错题重做 → 闭卷回忆与迁移任务 → 延伸和配套文件。不要把所有练习机械堆在长文之后。

**讲解深度标准**：知识解析是页面主体，写成完整的教学讲解，不是表格加三两句话的速查卡。每个关键点尽量回答：是什么 / 为什么这样设计 / 边界与坑在哪（附**真实报错文本或真实运行输出**）/ 与学习者已知体系如何对照（本库学习者有 Java 背景，正反对照都做）。深挖内容（历史原因、语言机制细节）收进折叠层分层呈现——主线不被淹没，但不许砍成空壳；「压缩到只剩结论」是被否掉过的形态。

**图示（按知识适配，非硬性）**：凡是需要读者在脑内自行拼装机制的环节（分流、过滤、数据流、决策、值域关系），优先配一张内联 SVG 手绘图。要求：

- 画机制不画名词：框图要展示「数据怎么流、什么被排除、什么被放行」，箭头带标签；
- `viewBox` 定尺寸、CSS `max-width:100%` 自适应；`<figure>` + `<figcaption>` 一图一论断；`role="img"` + `aria-label`；
- 配色沿用页面语义色（拦截=红、放行=绿、推荐=蓝），纯手写 SVG，无脚本、无外链、自包含；
- 一句话能说清的就写句子，不为形式配图。

**互动演示**：互动必须直接演示核心机制——可操作、参数可调、即时反馈，不是静态配图也不是装饰动效。首次进入显示一个初始例子；复杂过程支持逐步前进/回退并同步高亮状态；适合时先让学习者预测再揭示结果。明确演示是模拟而非真实编译或运行。机制确实不适合网页交互的主题（如硬件依赖），说明原因并提供替代形式（如交互式自测问答），不要硬凑。

**练习设计（两类分开，目的不同）**：

- **动手练习（写代码）**：给代码骨架和任务说明，学习者先在编辑框写自己的答案（草稿自动保存到本浏览器），写完再展开**默认隐藏**的参考答案与逐行讲解，自行对照。**不做浏览器内代码判分。**浏览器跑不了的语言检查（如 tsc）要诚实：参考答案附本地验证命令，把学习者引到 `示例代码/` 真跑，不假装能在线编译。
- **闯关练习（固定答案）**：选择 / 填空 / 多选，前端固定答案判分，答错可重做，每题必有解析并指回相关章节；报错类题目的选项和解析引用真实报错文本。成绩存本浏览器，提供错题重做与独立重置，重置不清阅读记录或动手练习草稿。
- **回忆与迁移**：结尾设置 3–5 个闭卷回忆问题和一个跨场景迁移任务；可给出 1/3/7 天轻量复习建议，但不伪造已创建外部提醒。八股速记只能辅助，不能替代回忆和真实验证。

### 知识类型分层设计

不同类型的知识点侧重不同，学习页的篇幅配比随之调整，不要用同一副骨架硬套：

| 知识类型 | 侧重 | 例子 |
| --- | --- | --- |
| 语言 / 类型系统类（TS、JS） | 知识解析与互动演示、动手练习并重；类型演化、报错文本要真实可验 | 收窄六式、事件循环 |
| 服务 / 中间件类（MySQL、Redis） | **重点在知识解析**：原理、流程、误区、八股追问写透；实际代码从简，能验证核心结论即可 | 事务隔离、持久化 |
| 工程思维类 | 知识解析 + 决策流程图 + 场景辨析为主，代码只做佐证 | 索引设计、缓存策略 |

### 系列内导航

同一系列的知识点（如 `前端/TypeScript/` 下的各点）通过**共享导航脚本**互连，模式如下：

1. 系列清单（id、名称、目录、文件名）只维护在共享脚本一处（如 `前端/TypeScript/系列导航.js`），**不在各页面复制清单**。
2. 每个页面只做两件事：`<body data-tsnav="知识点id">`，`</body>` 前引入 `<script src="../系列导航.js"></script>`。脚本自动挂载页首「系列位次条」（圆点进度 + 紧凑翻页）与页尾「上一页 / 下一页」卡片，并支持 ← / → 键盘翻页（输入框内、带修饰键时不触发）。
3. 旧格式页面同样可以接入（挂到其现有 HTML 入口上），在导航中以「旧格式」徽标注明。
4. 新增知识点时只在共享脚本的 SERIES 里补一条，全系列页面自动点亮，不改动任何旧页面。
5. 只有当系列内已有两个以上页面、且明确会继续增长时才建导航；孤立知识点不建。

## 示例代码

1. 至少一个真实代码文件，扩展名与主题匹配（`.java`、`.ts`、`.py`、`.go`、`.c`、`.sql`、`.html` 等）。
2. 示例必须直接验证学习页讲的核心概念，保持最小但完整，不加入无关工程复杂度。
3. 优先可直接运行；依赖硬件、服务或特定环境时，提供可验证的替代方式并明确说明限制。
4. 注释面向学习者：关键语句做什么、为什么这样写、执行顺序、预期现象。不给逐行重复代码字面的低价值注释。
5. 多文件时放 `示例代码/` 目录并提供 `README.md`：入口、依赖、运行命令、**预期结果**（含预期报错——故意留错让学习者见到真实报错文本是合法设计）。这份说明不能替代真实代码文件。
6. 示例代码与学习页的术语、步骤和输出必须一致。

## 验证与交付

1. **真实运行核实**：学习页引用的报错文本、运行输出、数值结论，必须在本机真实运行核实（tsc / node / mysql 等），不许凭记忆或推断写。
2. **学习页复验**：改动学习页后必须复验——脚本语法与 init 全链路可执行（推荐 node + `vm` 的 DOM 桩验证器模式：迷你 DOM 执行页面脚本，断言渲染、点击、判分、存储降级）、内部链接与相对路径正确、localStorage 降级不崩、内联 SVG 标签配平。
3. 运行 `node scripts/validate_learning_page.js <学习页.html>` 做静态检查，再运行 `node scripts/verify_page_runtime.js <学习页.html>` 在 Node 沙箱中执行页面脚本，验证初始化、目录、章节完成、首个练习反馈、代码草稿和存储禁用降级；页面专属互动步骤和练习答案仍需专项核对。最后按 `references/学习页设计规范.md` 的清单补做首次打开、再次打开、360px 移动端、键盘和打印体验验收。自动检查不能替代真实浏览器体验。
4. 示例代码真实运行；练习题逐题核对答案自洽。
5. 检查主题是否放进最合理的目录、有无重复内容、有无多余的中间层级。
6. 向用户说明主题路径、创建或更新的文件、验证结果（通过数/总数），以及任何环境限制。

用户的明确要求优先于本 Skill 的推荐做法；但不得在未说明的情况下省略最低交付物：`学习页.html` 与带详细注释的示例代码为所有新知识点必交；旧知识点不追溯。
