# 学习页设计与验收规范

在新建或重构 `学习页.html` 时阅读本规范。用统一体验降低学习成本，但按知识点本身设计讲解、图示、互动和练习，不机械填充模板。

## 1. 先设计学习路径

动笔前先在内部完成一份简短学习设计，不必额外交付文档：

- 明确学习者已经会什么、本页需要哪些前置知识；
- 写出 3–5 个可观察的学习目标，使用「能解释、能判断、能写出、能排查」等动词，避免「了解、熟悉」；
- 找出 1–3 个核心难点，并为每个难点安排图示、演示或练习中的至少一种；
- 确定学会后的验收证据，例如能预测输出、能修正报错、能完成一段代码；
- 先安排学习闭环，再扩写正文。不要为了显得丰富而堆砌边角知识。

## 2. 用章节闭环组织内容

页面整体采用：

1. 主题引入：解决什么问题、前置知识、学习目标；
2. 核心章节：每章完成一次「目标 → 讲解 → 图示/演示 → 即时检验 → 小结」；
3. 综合练习：跨越多个章节的代码任务与固定答案题；
4. 回忆与迁移：闭卷回忆、错题重做、本地验证、前置/下一站。

遵守以下规则：

- 在对应知识点后尽早安排一道短练习，不把全部练习堆到长文末尾；
- 每章只承担一个主要论断，标题尽量表达结论或问题，而不只是罗列名词；
- 每章末尾用 1–3 句提炼「本章记住」，总结本章新信息，不重复整段正文；
- 主线必学内容直接呈现；历史背景、少见边界和进阶机制放入 `details` 深挖层；
- 保留完整教学深度，不以「减轻认知负担」为理由删成速查卡；
- 长页面提供上一节/下一节或清晰目录，避免只能靠连续滚动定位。

## 3. 建立清楚的视觉层级

### 阅读排版

- 正文字号以 `16px` 为基准，行高约 `1.75–1.9`；代码以 `13.5–14.5px` 为基准；不要用小字换取一屏容纳更多内容；
- 正文阅读列控制在约 `720–820px`；图示、代码和互动演示可以适度加宽，但避免长段落横跨整个宽屏；
- 使用真实标题层级：页面仅一个 `h1`，章节使用 `h2`，章内使用 `h3/h4`；不要只靠加粗模拟标题；
- 用字重、字号、间距和少量语义色区分层级，不为每节套同样重量的装饰卡片；
- 对「核心结论、真实报错、常见误区、进阶拓展」使用不同且一致的提示样式；
- 每段只讲一个重点。连续长段落拆成短段、步骤或例子，但不把一切改写成碎列表。

### 视觉与语义

- 默认浅色、低干扰背景，正文与背景对比度至少满足 WCAG AA；
- 红/绿不能成为判断对错的唯一依据，同时提供文字、图标或边框形状；
- 动画只服务于状态变化，不用装饰动效分散注意；支持 `prefers-reduced-motion`；
- 页面在 360px 宽度下无横向溢出；宽表格单独放入可横向滚动容器；
- 提供基本打印样式，隐藏导航与操作按钮，展开的关键知识仍可打印。

## 4. 让导航和进度反映真实学习状态

- 桌面端提供章节目录并高亮当前阅读位置；移动端提供可展开的等价目录，不直接隐藏全部导航；
- 顶部一句话说明本页怎样学，但不要用大面积黄色警告条占据首屏；
- 阅读进度、演示操作和答题成绩分别统计并明确命名，不把「答题数」冒充整页学习进度；
- 章节完成状态应来自明确操作或可解释的规则，不能仅因滚动到底就宣称已经掌握；
- 保存上次阅读位置，再次打开时提供「继续学习」，不强行跳转而打断学习者；
- 重置操作按「阅读记录、闯关成绩、代码草稿」分开；危险重置前二次确认；
- 所有持久化均通过带 `try/catch` 的存储适配层，禁用存储时仍可在当前页面完成学习。

## 5. 把互动做成推理过程

- 首次进入即显示一个可理解的初始例子，不要求学习者先猜按钮用途；
- 为复杂过程提供上一步、下一步或自动播放，并同步高亮当前代码行、数据位置或状态；
- 在展示结果前先让学习者预测，再给出反馈与原因；
- 明确演示简化了哪些真实机制，不把动画模拟冒充真实编译或运行；
- 每个互动只服务一个核心问题，避免无教学价值的按钮、计数器和装饰效果；
- 互动不能依赖鼠标悬停，键盘和触屏也能完成主要操作。

## 6. 练习、反馈与复习

- 动手练习先给任务、骨架和提示，再默认隐藏参考答案；草稿自动保存并提供复制代码按钮；
- 固定答案题作答后立即给出「为什么对、为什么错」，允许重做；多选题没有作答时给出提示而非直接判错；
- 答错后指向对应章节，不只展示标准答案；
- 提供「只看重做错题」或等价入口；重做不覆盖此前代码草稿；
- 结尾设置 3–5 个不看资料能回答的回忆问题，以及一个迁移任务；
- 复习建议保持轻量，例如「1 天后重做错题、3 天后闭卷回忆、7 天后完成迁移任务」，不伪造外部提醒已经创建；
- 「八股速记」只作为辅助，不能替代闭卷回忆和实际验证。

## 7. 可访问性与离线质量

- 所有按钮使用 `button`，可点击元素具备可见焦点，不用只有点击事件的 `div` 模拟按钮；
- 表单控件有 `label` 或等价可访问名称；动态结果通过 `aria-live` 或明确状态文本反馈；
- SVG 使用 `role="img"` 与 `aria-label`，复杂图另有文字解释；
- 目录锚点不被粘性顶栏遮挡，使用 `scroll-margin-top`；
- 所有资源自包含；共享系列导航是允许的本地相对依赖，离线双击时仍需正常降级；
- 外部链接仅用于延伸阅读，不得成为理解主线或运行页面的必要条件。

## 8. 交付前体验验收

至少检查以下真实场景：

1. 首次打开：10 秒内能说出学什么、先做什么、怎样验证学会；
2. 章节学习：每个核心难点附近都有操作或自测，结果有解释；
3. 再次打开：能选择继续上次位置，代码草稿与答题状态仍在；
4. 存储禁用：页面不崩，学习、互动和答题仍可用；
5. 360px 移动端：目录可用、按钮可点、正文不换行异常、页面无整体横向滚动；
6. 键盘操作：目录、按钮、练习和答案展开可用，焦点清楚；
7. 打印/复制：能打印清洁正文，示例代码可复制且不含行号污染；
8. 内容一致：页面、练习答案、示例代码和真实运行输出一致。

使用 `scripts/validate_learning_page.js` 做静态与脚本检查，但自动检查不能替代上述人工体验验收。
