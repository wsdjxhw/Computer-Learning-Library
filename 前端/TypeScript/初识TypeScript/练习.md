<summary>参考答案（先自己做完再看）</summary>

### 1.

TS 是 JS 的**超集 + 编译期类型检查器**：任何合法 JS 都是合法 TS，TS 额外的部分（类型标注、interface、泛型）只用于编译期检查，编译产物是纯 JS。

浏览器**不认识** `.ts`——世界上没有"TS 引擎"，`.ts` 必须先由 `tsc` 编译成 `.js` 才能运行（类型擦除后产物就是等价 JS）。工程里这步由构建工具自动完成，开发者感知不到，但原理如此。

### 2.

类型擦除 = tsc 编译时删除所有类型标注，产物只剩运行时需要的代码。`interface`、`type`、泛型参数、`as` 断言全部被擦掉——它们是"纯类型"结构，只活在编译期。

**enum 例外**：它有运行时行为（编译成真实的对象，还带 `0 ↔ "Red"` 双向映射），所以保留并"展开"成一段 JS 代码（见知识详解 2.2 / 互动演示片段 C 的实测产物）。

验证办法：编译前后对比——`npx -p typescript@5 tsc --target ES2020 01-类型标注与类型擦除.ts`，用编辑器并排打开 `.ts` 和 `.js`，所有 `: 类型` 都没了。

### 3.

1. **会生成**：`noEmitOnError` 默认 `false`，报错照样产出（这也是渐进迁移的设计考量）；
2. 错误 2 **静默错值**：`order2.amout` 运行时得到 `undefined`，打印 `undefined`，程序继续跑；错误 4 **当场崩溃**：`TypeError: "hello".toUppercase2 is not a function`，进程退出（exit code 1）；
3. **静默错值更危险**：崩溃至少立刻暴露，静默错值（`undefined`、`NaN`、`112.999…`）会带着错值继续往下游传，可能在很远的地方才炸出诡异现象——这正是要在编译期把它们拦掉的理由。

### 4.

三段式：**文件(行,列)** = `02-编译期拦截.ts(18,36)`——第 18 行第 36 列；**错误码** = `TS2551`；**人话描述** = 属性 `amout` 在类型 `{ id: number; amount: number; }` 上不存在，还附了纠正建议 `Did you mean 'amount'?`。

TS2551 与 TS2339 都是"属性不存在"，区别在 **2551 附带 Did you mean 建议**（tsc 找到了相近的名字），2339 没有建议。看到 2551，九成直接按建议改拼写就行。

### 5.

TS7006 = **隐式 any**：参数没标类型，tsc 推导不出，默认按 any 处理；strict 模式（noImplicitAny）禁止这种"沉默的 any"。

修法：① 给参数标类型：`function greet(who: string)`；② 如果类型确实难写（如回调），标 `unknown` 再收窄（后续知识点展开），但不要写 `any` 蒙混。

### 6.

失守点：

- `readConfig()` 返回值标成 `any` —— **第 1 行起检查就失效**（源头失守）；
- A 行：any 赋给 `{ theme: string }` 不报错——**传染**，null 也能这样"混"进来；
- B 行：如果 raw 实际是 null，`config.theme` 运行时直接 `TypeError`（编译期无感）；
- C 行：参数标 any——**又一个失守入口**，函数内部对 c 的所有操作脱检。

最小修复（只用本知识点学过的东西）：

```ts
const raw: unknown = readConfig();           // unknown：不可直接用，逼你表态
if (typeof raw === 'string' && raw.length > 0) {
  const config: { theme: string } = JSON.parse(raw);  // 本例仍属外部数据，严谨做法见题 7
  console.log(config.theme.toUpperCase());
}
function apply(c: { theme: string }) {       // 参数标真实形状，别用 any
  console.log(c.theme);
}
```

核心口诀：**any 是"检查器闭嘴"，unknown 是"先证明再用"**。

### 7.

不同意。`JSON.parse` 的返回类型是 any，`: User` 标注只是"担保"，编译器没有验证过 JSON 的实际内容——字段拼错、类型不符、缺字段都会在运行时才露馅（知识详解 2.4 的 3307 就是实例）。

两层防线：

1. **编译期**：给业务代码标好类型（函数参数、变量、接口返回值的类型定义）——挡住"自己写出来的"类型错误；
2. **运行时**：对外部数据先校验再使用——手写守卫（typeof/字段检查）或用校验库（Zod 等，实战知识点加餐），校验通过后再交给类型系统。

一句话：**类型是标注，不是保证**；代码内部的类型错误编译期拦，外部数据的错误必须运行时校验。

### 8.

```ts
function average(nums: number[]): number {
  const sum = nums.reduce((a, n) => a + n, 0);
  return sum / nums.length;
}
function label(score: number): string {
  return score >= 60 ? '及格' : '不及格';
}
```

验证：存成 `练习8.ts` 执行 `npx -p typescript@5 tsc --noEmit 练习8.ts` 无输出（零错误）；加一行 `label('A');` 再编译，报 `error TS2345: Argument of type 'string' is not assignable to parameter of type 'number'`。对照 Java：`average(double[] nums)` / `String label(int score)`——参数和返回值是函数的"契约"，必须显式写。
