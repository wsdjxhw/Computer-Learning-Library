# 数组

## 学习目标

- 理解数组"连续内存 + 下标访问"的本质，能解释为什么随机访问是 O(1)。
- 理解插入、删除为什么要搬移元素，从而是 O(n)。
- 理解动态数组（如 Python 的 `list`）的容量、长度与扩容机制。
- 掌握赋值、浅拷贝、深拷贝的区别，避开最常见的别名陷阱。

**前置知识**：基本的 Python 语法（变量、循环、函数）。
**适用范围**：所有编程语言通用的概念；示例语言为 Python，机制在 C/C++/Java 等语言中同样成立（且更"裸露"）。

---

## 一、数组解决什么问题

程序里经常要处理"一组同类型的数据"：100 名学生的成绩、一万条日志的时间戳。如果每个数据都用一个独立变量，代码无法循环处理。**数组把一组数据放进一段连续的内存里，并允许用下标（编号）直接定位任何一个元素**——这是最基础、使用最广泛的数据结构。

## 二、核心原理

### 2.1 连续内存与寻址公式：为什么访问是 O(1)

数组申请的是一整段连续内存。因为每个元素大小相同且紧密排列，第 `i` 个元素的地址可以用公式直接算出来：

```text
元素 i 的地址 = 起始地址 + i × 单个元素大小
```

无论 `i` 是 0 还是 500 万，都只做一次乘法加法，所以**按下标访问的时间与数组长度无关，是 O(1)**。

```text
下标:    0      1      2      3      4
      ┌──────┬──────┬──────┬──────┬──────┐
      │  90  │  85  │  78  │  92  │  66  │
      └──────┴──────┴──────┴──────┴──────┘
        ↑ 起始地址                ↑ 起始地址 + 4×元素大小
```

### 2.2 插入与删除：为什么是 O(n)

连续性是双刃剑。在中间插入或删除一个元素，为了保持"紧密排列"，后面的元素必须整体搬移：

```text
在下标 1 插入 15：                  删除下标 0 的元素：
[10, 20, 30, 40]                    [10, 15, 20, 30, 40]
[10, __, 20, 30, 40]  ← 腾空位      [__, 15, 20, 30, 40]  ← 出现空洞
[10, 15, 20, 30, 40]  ← 20/30/40   [15, 20, 30, 40, __]  ← 后面全部前移
                          全部后移
```

平均要搬移约一半（n/2）个元素，时间复杂度 O(n)。**只有操作发生在末尾（`append` / `pop()`）时才不需要搬移**。

### 2.3 动态数组：容量、长度与扩容

"静态数组"（如 C 的 `int a[10]`）容量固定。日常使用的 `list`、`ArrayList`、`vector` 都是**动态数组**：对外表现成可无限增长，内部维护两件事——

- **长度（size）**：当前存了几个元素；
- **容量（capacity）**：实际申请的内存能放几个元素，容量 ≥ 长度。

当长度追上容量时触发扩容：申请一段更大的新内存（通常是原来的约 2 倍），把所有元素整体搬过去。因此扩容时刻是"一次性 O(n)"，摊到之前每次 `append` 上约为 O(1)，称为**均摊 O(1)**。观察内存占用会看到"长时间不变、突然跳一档"的阶梯（见示例第 3 段）。

### 2.4 复杂度速查

| 操作 | 复杂度 | 原因 |
| --- | --- | --- |
| 按下标访问 `a[i]` | O(1) | 寻址公式一次算出 |
| 末尾追加 `append` | 均摊 O(1) | 偶尔触发扩容搬迁 |
| 中间插入 / 删除 | O(n) | 搬移后半段元素 |
| 查找（无序，按值） | O(n) | 只能逐个比对 |
| 查找（有序，二分） | O(log n) | 见延伸方向 |

示例文件：`示例代码.py`（与下述段落编号一一对应）

**第 1 段：下标随机访问**。直接用 `scores[0]`、`scores[4]` 取值，并演示负下标和越界抛出的 `IndexError`。越界不是"返回空值"而是直接报错，这是访问下标前必须检查边界的提醒。

**第 2 段：手写插入 / 删除**。故意不用 `list.insert`，手动从后向前挪元素（插入）和从前向后挪（删除），把 O(n) 的搬移过程放大给读者看。注释里特别强调搬移方向：插入必须**从后往前**挪，否则前面的值会覆盖掉还没搬走的值。

**第 3 段：观察扩容**。用 `sys.getsizeof` 监控 `append` 过程中的内存字节数，出现 56→88→120→184→248 的阶梯跳变——跳变点就是扩容时刻。数值因 Python 版本而异，关键看"阶梯"这个形态。

**第 4 段：线性查找**。在无序数组中找 15 需要 5 次比较；记录比较次数是为了直观感受"最坏要走完整个数组"。

**第 5 段：别名陷阱**。`b = a` 后改 `b[0]`，`a[0]` 也变了（同一对象）；浅拷贝 `a.copy()` 只复制外层，嵌套的内层列表仍然共享；`copy.deepcopy` 才完全独立。

## 四、常见误区与边界条件

| 误区 | 后果与纠正 |
| --- | --- |
| 边遍历边 `remove` | `for x in a: a.remove(x)` 会跳过元素（删除导致后续元素前移、下标错位）。应遍历副本或收集待删下标 |
| 混淆赋值与拷贝 | `b = a` 不产生新数组；需要独立副本时用 `copy()` / `deepcopy()` |
| 以为浅拷贝万事大吉 | 嵌套结构（列表的列表）内层仍共享，改一处动两处 |
| 越界访问 | 下标合法范围是 `[0, len-1]`，越界直接 `IndexError`；循环边界写成 `range(len(a) + 1)` 是高频错误 |
| 忽略空数组 | 对空数组取 `a[0]`、`a[-1]` 立即报错，操作前先判空 |

**排查思路**：出现"数组莫名变化"，优先怀疑别名共享——用 `id(a) == id(b)` 或 `is` 判断是否同一对象。

## 五、实际应用与取舍

- **适合数组**：读多写少、按下标访问、需要随机访问的场景（查找表、缓冲区、矩阵、`DataFrame` 底层）。
- **不适合数组**：频繁在头部或中间插入删除（每次 O(n) 搬移）——这正是[链表](../链表/)的用武之地；按键快速查找则交给[哈希表](../哈希表/)。
- 工程直觉：语言内置的动态数组（Python `list`、Java `ArrayList`、C++ `vector`、Go `slice`）已把扩容做好，绝大多数场景直接使用即可；只有面试或底层学习才需要手写。

## 六、可继续学习的方向

- [链表](../链表/)：用指针换取 O(1) 插入，与数组互为镜像。
- [哈希表](../哈希表/)：把"按值查找"从 O(n) 做到接近 O(1)。
- 二分查找（有序数组上的 O(log n) 查找，属算法主题）。
- 跳表、动态数组扩容策略的均摊分析。
