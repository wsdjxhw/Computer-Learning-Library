# 队列

## 学习目标

- 理解队列"先进先出（FIFO）"的语义与典型用途。
- 明白为什么 `list.pop(0)` 不适合做出队操作。
- 掌握环形队列"取模绕环"的原理，能手写一个固定容量队列。
- 了解 `collections.deque` 这一工程标准选择。

**前置知识**：[数组](../数组/)、[栈](../栈/)（对比着学最有效）。
**适用范围**：所有语言通用；示例语言为 Python。

---

## 一、队列解决什么问题

队列 = 只允许**队尾进、队头出**的线性结构，保证**先进先出**（First In, First Out）。它表达的是"公平"：到达顺序即处理顺序。凡是"排队"的场景——任务调度、消息传递、缓冲区、广度优先搜索——底层都是队列。

## 二、核心原理

### 2.1 FIFO 与栈的对比

```text
栈（LIFO）                    队列（FIFO）
   ↑↓ 只在栈顶                ↑ 出队  ↓ 入队
┌─────┐                    ┌───────────┐
│  3  │ 最后进，最先出        │ 1 2 3 4 5 │ 最先进的 1 最先出
│  2  │                    └───────────┘
│  1  │                     队头          队尾
└─────┘
```

### 2.2 为什么 list 不适合做队列

Python `list` 的 `pop(0)` 删除首元素后，后面所有元素要整体前移一格（参见[数组](../数组/)的搬移原理），单次 O(n)，出队 n 次就是 O(n²)。`collections.deque`（双端队列）两端增删都是 O(1)，示例第 1 段用 30000 次出队的实测时间对比了两者（本机约 793 毫秒 vs 2.5 毫秒）。

### 2.3 环形队列：用数组实现 O(1) 出队

数组做不到"删头不搬移"，但可以换个思路：**出队后不搬移元素，只把队头标记 `front` 往前挪一格**。队尾追到数组末尾时，通过**取模运算**绕回开头复用空出来的格子——把直数组"弯"成环：

```text
容量 4。连入 10,20,30,40 装满，出队 10、20 腾出前两格，再入队 50：

装满时:   [10] [20] [30] [40]    front=0, count=4
出队两次: [空] [空] [30] [40]    front=2, count=2  ← 只挪 front 标记，不搬移元素
再入 50:  [50] [空] [30] [40]    rear = (front+count) % 4 = (2+2) % 4 = 0
                                   → 50 绕回下标 0，数组首尾相接成"环"
```

- 队尾下标不由单独变量维护，而是 `(front + count) % capacity` 现算，`front` 与 `count` 两个变量就完整描述了队列状态。
- 判满：`count == capacity`；判空：`count == 0`。（另一种常见设计是存 `rear` 指针并牺牲一个空位来区分空/满，效果等价。）
- 代价：容量固定。满了要么报错，要么覆盖最旧数据（很多日志缓冲区选后者）。

### 2.4 操作复杂度

| 操作 | 数组 list | 环形队列 | deque |
| --- | --- | --- | --- |
| 入队（尾进） | O(1) | O(1) | O(1) |
| 出队（头出） | **O(n)** | O(1) | O(1) |
| 随机访问 | O(1) | — | O(n) |

## 四、常见误区与边界条件

| 误区 / 边界 | 说明 |
| --- | --- |
| 用 `list.pop(0)` 做队列 | 隐性 O(n) 出队，规模一大性能雪崩；用 deque |
| 混淆 `pop()` 与 `popleft()` | deque 的 `pop()` 是从**尾部**弹（栈行为），队头出队必须 `popleft()` |
| 环形队列忘记取模 | front/rear 走到数组末尾后越界，取模才是"环" |
| 队满 / 队空判断 | `count` 与容量比较即可；若用 front/rear 双指针设计，空和满的条件可能撞车，需牺牲一格或额外计数 |
| 空队出队 | 与空栈弹出一样要显式处理，抛异常优于返回 None |

**排查思路**：怀疑队列逻辑出错时，打印每步操作后的 front、count 和内部数组（像示例的 `internal_view` 那样），绕环过程一帧一帧看。

## 五、实际应用与取舍

- **任务调度**：线程池任务队列（`queue.Queue` 还保证线程安全）、打印队列、消息队列（RabbitMQ/Kafka 的"队列"语义同源）。
- **算法**：广度优先搜索（BFS，见[图](../图/)第 2、3 段）、树的层序遍历、拓扑排序。
- **缓冲**：IO 缓冲区、播放器缓冲（固定容量的环形缓冲区正是第 2 段的结构，常用于音视频、嵌入式串口收发）。
- **取舍**：要"最近"用[栈](../栈/)，要"最早"用队列，两头都要用 deque；需要按优先级插队则用[堆](../堆/)实现的优先队列。

## 六、可继续学习的方向

- [堆](../堆/)：优先队列——按优先级而非到达顺序出队。
- [图](../图/)：BFS 中队列如何带来"按层扩展"与最短路径。

- `queue.Queue` / `asyncio.Queue`：线程/协程安全的队列差异。
