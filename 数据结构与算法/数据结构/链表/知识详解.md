# 链表

## 学习目标

- 理解链表"节点 + 指针"的存储方式，以及它与[数组](../数组/)的本质区别。
- 能手写单向链表的插入、查找、删除、反转，并理解每一步指针操作的顺序。
- 掌握"前驱节点"这一链表操作的核心角色。

**前置知识**：[数组](../数组/)（理解它的不足，才知道链表为什么存在）、Python 的类与对象基础。
**适用范围**：所有支持引用/指针概念的语言；示例语言为 Python。

---

## 一、链表解决什么问题

[数组](../数组/)插入、删除要 O(n) 搬移元素，因为它必须保持内存连续。链表反其道而行：**放弃连续内存，每个节点自带一个"下一站"指针，用指针把散落各处的节点串起来**。这样插入、删除只需改动相邻节点的指针，与链表长度无关。

## 二、核心原理

### 2.1 节点与链表结构

```text
head
 ↓
┌────┬───┐    ┌────┬───┐    ┌────┬───┐    ┌────┬───┐
│ 10 │ ●─┼──> │ 20 │ ●─┼──> │ 30 │ ●─┼──> │ 40 │ ─ │──> NULL
└────┴───┘    └────┴───┘    └────┴───┘    └────┴───┘
  数据  指针      数据  指针     数据  指针     数据  指针
```

- **节点（Node）**= 数据域 + 指针域；`next = None` 表示链尾。
- **链表对象只持有 `head`**，其余节点都要从 head 顺着 `next` 走过去。
- 单向链表只能往后走，不能回头（双向链表额外有 `prev` 指针）。

### 2.2 两种插入的代价对比

| 操作 | 步骤 | 复杂度 |
| --- | --- | --- |
| 头插 | 新节点.next = head；head = 新节点 | O(1) |
| 尾插（无尾指针） | 从 head 走到最后一个节点再接上 | O(n) |
| 删除给定节点的前驱已知 | 前驱.next 跨过被删节点 | O(1) |
| 查找 / 按值删除 | 从 head 逐个比对 | O(n) |

头插的两步**顺序不能反**：必须先让新节点接住原 head，再移动 head。若先改 head，原链表就"失联"了——这是链表代码最经典的一类 bug。

### 2.3 删除：前驱节点接手法

删除目标节点时，真正要改的是它的**前驱**：`prev.next = prev.next.next`，让指针直接跨过被删节点。

```text
删除 20：            ┌──────────────┐
┌────┐   ┌────┐   ┌────┐
│ 10 │   │ 20 │   │ 30 │      10.next 原来指向 20，
└────┘   └────┘   └────┘      改成指向 30，20 就脱离了链
  prev     被删      next
```

麻烦在于：单向链表拿到一个节点时**拿不到它的前驱**，所以删除仍要从 head 出发先找前驱，整体 O(n)。删除头节点是特例（没有前驱），直接 `head = head.next`。

### 2.4 反转：三指针法

维护 `prev`（已反转部分的新头）、`current`（当前处理）、`nxt`（暂存下一站）。每轮四步：暂存 → 掉头 → prev 前进 → current 前进。关键同样是顺序：**先存 `nxt` 再改 `current.next`**，否则一掉头后面全丢。

## 四、常见误区与边界条件

| 误区 / 边界 | 说明 |
| --- | --- |
| 先改指针后存引用 | 顺序写反导致后半段链表永久丢失；写链表代码时先问"改这个指针前，它原来指的东西存下来了吗" |
| 忘记空链表 | 插入第一个节点（head 为 None）、删除唯一的节点都要单独处理，示例的尾插和删除都展示了对应分支 |
| 忘记删除头节点 | 头节点没有前驱，套用"前驱接手"逻辑会直接漏掉，需特判 |
| 以为链表查找是 O(1) | 链表只是插入删除快（且要已知位置），按值查找仍是 O(n) |
| 内存泄漏意识 | Python 有垃圾回收；在 C/C++ 里被摘下的节点要手动 `free`，否则泄漏 |

**排查思路**：链表 bug 多表现为"死循环"（成环）或"后半段消失"。用纸笔画出每步指针指向，或打印 `to_list()` 分步观察，是最有效的调试方式。

## 五、实际应用与取舍

- **适合链表**：频繁在已知位置插入/删除（如 LRU 缓存的淘汰队列）、实现[栈](../栈/)和[队列](../队列/)的底层（`deque` 即块状双端链表思想）、需要 O(1) 合并两个序列。
- **不适合链表**：随机访问、二分查找、缓存友好性差（节点分散，CPU 预取失效）。
- 实际工程中纯链表出场率低于数组/动态数组；它的更大价值是**思想载体**——指针操作是树、图、HashMap 桶内冲突链的基础，也是面试高频题（反转、找环、合并有序链表）。

## 六、可继续学习的方向

- 双向链表与循环链表（`collections.deque` 的底层就是双端结构）。
- 快慢指针技巧：找中点、判断环（Floyd 判圈）。
- [哈希表](../哈希表/)：链地址法在桶内挂的就是单链表。
- 跳表：给链表加索引实现 O(log n) 查找（Redis 有序集合的底层之一）。
