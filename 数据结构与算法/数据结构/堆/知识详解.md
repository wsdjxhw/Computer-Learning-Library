# 堆

## 学习目标

- 理解堆（本文以**最小堆**为例）的性质：只保证"父节点 ≤ 孩子"，不要求全序。
- 掌握堆的数组表示法：不用指针，下标运算即树的结构。
- 能手写上浮（sift-up）与下沉（sift-down），理解 push/pop 的完整流程。
- 会用堆解决 Top-K 问题，并了解标准库 `heapq`。

**前置知识**：[数组](../数组/)（堆就存在数组里）、完全二叉树的概念、对数复杂度 log n 的直觉。
**适用范围**：所有语言通用；示例语言为 Python。

---

## 一、堆解决什么问题

很多场景只需要"**当前最大/最小的一个**"，不需要整体有序：任务调度总先跑优先级最高的、海量数据只取前 K 个、每次动态插入后都要快速取出最小值。全排序代价 O(n log n) 且难以应对"边插边取"。堆是一个折中：**只维持"父 ≤ 子"这一条约束**，换取最小值永远在固定位置（下标 0），插入和取出都只要 O(log n)。

## 二、核心原理

### 2.1 堆的性质与数组表示

最小堆是一棵**完全二叉树**（除最后一层外每层全满，最后一层从左到右排列），且**每个父节点的值 ≤ 它的孩子**。注意它**不保证**左右孩子之间、兄弟子树之间的大小关系——这正是它比全序树（如[二叉搜索树](../二叉搜索树/)）维护成本更低的原因。

完全二叉树"从上到下、从左到右"编号后，可以用数组直接存储，**下标运算就是指针**：

```text
数组:  [1, 4, 2, 9, 8, 7]        对应的树:
下标:    0  1  2  3  4  5              1[0]
                                    /     \
父(i)   = (i-1) // 2              4[1]     2[2]
左孩子  = 2i + 1                 /   \     /
右孩子  = 2i + 2               9[3] 8[4] 7[5]
```

- 每层下标范围恰是上一层的 ×2+1、×2+2，父 = (i-1)//2 对左右孩子都成立。
- 最小值必然堆顶 = `data[0]`（每条"父 ≤ 子"链的顶端）。
- 空间零浪费、缓存友好，这就是工程里堆几乎都用数组实现的原因。

### 2.2 上浮与下沉：堆的两个核心动作

堆的一切操作都由两个动作组合而成，每次调整都沿着一条"祖先链"走，代价 ≤ 树高 = O(log n)：

- **上浮（sift-up）**：新元素加在数组**末尾**（保持完全二叉树形态），若它比父小就和父交换，一路换到"不比父小"为止——push 的后半段。
- **下沉（sift-down）**：堆顶元素被换走后，把数组末尾元素放到堆顶，与**较小的**孩子比较，比孩子大就交换，一路换到"不比孩子大"为止——pop 的后半段。和较小孩子交换是为了让较小的那个升上来，维持父 ≤ 子。

两处循环都在"已经满足堆性质"时**提前退出**，不走到叶子——这是堆操作高效的关键。

### 2.3 push 与 pop 的完整流程

```text
push(v):  末尾追加 v → 上浮        pop():  记下堆顶 → 末尾元素放入堆顶
[9,4,7] push 1:                       → 下沉 → 返回记下的最小值
[9,4,7,1] → 1 与父 9 交换            [1,4,7,9,8] pop:
[1,4,7,9] → 1 与父 9? 不，           末尾 8 放堆顶 → [8,4,7,9]
  已到顶，结束                       8 与较小孩子 4 交换 → [4,8,7,9] 结束
```

为什么 pop 不直接删堆顶、把后面元素整体前移？那会破坏完全二叉树形态（下标错位），O(n)；"末尾补位 + 下沉"保持形态且只需 O(log n)。

### 2.4 复杂度速查

| 操作 | 复杂度 | 说明 |
| --- | --- | --- |
| 取最值 `peek` | O(1) | 就在下标 0 |
| `push` | O(log n) | 末尾追加 + 上浮 |
| `pop` | O(log n) | 末尾补位 + 下沉 |
| 建堆（`heapify`） | O(n) | 自底向上下沉所有非叶节点，比逐个 push 的 O(n log n) 更优 |

## 四、常见误区与边界条件

| 误区 / 边界 | 说明 |
| --- | --- |
| 以为堆是全序的 | 堆只保证父子偏序；数组本身不是有序的，遍历一遍找"第二大"得不到正确答案 |
| 想要最大堆却用小堆语义 | Python 无内置最大堆，惯用技巧是存负数（`heappush(h, -x)`，弹出后再取负） |
| pop 后忘记末尾补位 | 直接删堆顶会让下标错位、形态崩坏；必须"末尾补位 + 下沉" |
| 空堆 peek/pop | 先判空，抛异常优于返回 None |
| Top-K 方向搞反 | 找**最大** K 个用**小**堆守门；找最小 K 个用大堆（或直接 nsmallest） |

**排查思路**：验证一个数组是不是合法堆，写个函数遍历所有 i 检查 `data[parent(i)] <= data[i]` 即可；调试 push/pop 时打印每步交换后的数组（像示例第 3 段那样）。

## 五、实际应用与取舍

- **优先队列**：任务调度、Dijkstra 最短路、A* 搜索的开放集、合并 K 个有序链表。
- **Top-K / 实时统计**：热搜榜、推荐召回、监控告警的"最差前 N"。
- **堆排序**：最坏 O(n log n)、原地 O(1) 额外空间，但不稳定、缓存局部性不如快排。
- **取舍**：要"快速取最值 + 动态插入"用堆；要全序遍历/范围查询用[二叉搜索树](../二叉搜索树/)；数据静止不动就排序后用数组。
- 语言对照：Python `heapq`（小堆）、Java `PriorityQueue`、C++ `priority_queue`（默认大堆）。
