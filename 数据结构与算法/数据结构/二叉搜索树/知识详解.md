# 二叉搜索树

## 学习目标

- 理解二叉搜索树（BST）"左小右大"的性质，以及它如何把查找做成 O(log n)。
- 能手写插入、查找、中序遍历与删除（三种情形）。
- 理解"顺序插入导致退化成链表"的问题，知道平衡树为什么存在。

**前置知识**：[数组](../数组/)与[哈希表](../哈希表/)的查找复杂度（对比着理解）、递归函数基础。
**适用范围**：所有语言通用；示例语言为 Python。

---

## 一、二叉搜索树解决什么问题

[数组](../数组/)按值查找 O(n)；[哈希表](../哈希表/)做到平均 O(1) 但**毫无顺序**——没法回答"比 40 大的最小值是谁""区间 [30, 60] 内有哪些键"。BST 用一棵有序的二叉树同时拿到两样东西：**查找每步排除一半（理想 O(log n)），中序遍历天然升序**。它是数据库索引、内存有序表的基础形态。

## 二、核心原理

### 2.1 BST 性质：左小右大

对**每个**节点都成立（不只是直接孩子）：

```text
            50            50 的左子树全部 < 50 < 右子树全部
          /    \          30 的左子树全部 < 30 < 右子树全部
        30      70        ……逐层递归成立
       /  \    /  \
      20  40  60  80
```

### 2.2 查找与插入：每步排除一半

从根开始，目标比当前节点小往左、大往右：

```text
查找 40 的路径: 50(右拐?40<50→左) → 30(40>30→右) → 40 命中
查找 45 的路径: 50 → 30 → 40 → 走到空位，不存在
```

理想情况下每比较一次就扔掉一半子树，复杂度 O(log n)。插入是同一逻辑：找到空位把新节点放进去。相等值通常直接忽略（BST 不存重复）。

### 2.3 中序遍历：天然升序

按"左 → 根 → 右"的顺序访问每个节点。由左小右大性质可推出：输出必然升序。上图中序遍历得到 `[20, 30, 40, 50, 60, 70, 80]`，与插入顺序无关——这是验证一棵 BST 是否合法的最常用手段。

### 2.4 删除：三种情形

| 情形 | 处理办法 |
| --- | --- |
| 叶子节点（无孩子） | 直接摘除 |
| 只有一个孩子 | 孩子顶替被删节点的位置 |
| 有两个孩子 | 找**右子树的最小值**（中序后继，即右子树一路向左走到底）覆盖被删节点的值，再删除那个后继节点 |

后继为什么合法：它大于左子树的所有值，又小于右子树中其他所有值，是唯一放得进这个位置、不破坏左小右大的值。

### 2.5 退化：BST 的命门

BST 的复杂度取决于**树高**，树高取决于**插入顺序**。同样 7 个值：

```text
[50,30,70,20,40,60,80] → 树高 3（矮胖，接近平衡）     50
                                                /    \
平衡树查找 80: 2 步                                 30      70
                                                 / \    /  \
[20,30,40,50,60,70,80] 升序插入                    20 40  60  80
→ 每个都往右塞，退化成"链表"，树高 7

退化树:  20 → 30 → 40 → 50 → 60 → 70 → 80（全部只有右孩子）
查找 80 要走 7 步，复杂度恶化到 O(n)
```

**平衡树**（AVL、红黑树）在插入/删除时通过旋转主动把树高压在 O(log n)：AVL 严格平衡（查多改少），红黑树近似平衡（增删更频繁时更划算）。C++ `map`、Java `TreeMap`、Linux 进程调度用的就是红黑树。

## 四、常见误区与边界条件

| 误区 / 边界 | 说明 |
| --- | --- |
| 只比较直接孩子 | BST 性质要求整棵子树都左小右大；`30` 放在 `50` 的左子树里但 `> 40` 就是非法 BST |
| 以为 BST 一定 O(log n) | 最坏退化成链表 O(n)；只有平衡的 BST 才是 O(log n) |
| 删除双孩子节点时找错接班人 | 必须用中序后继（右子树最小）或中序前驱（左子树最大），随便拿右孩子顶替会破坏顺序 |
| 忘记处理"值不存在" | delete/search 对不存在的值要安全返回，示例的 `_delete` 走到 `None` 即返回 |
| 递归深度 | 极端退化树会让递归调用栈很深，Python 默认递归上限约 1000 |

**排查思路**：怀疑树写坏了，最快的体检就是**中序遍历**——输出不升序，性质必然被破坏；再配合打印树高判断是否退化。

## 五、实际应用与取舍

- **适合**：需要**有序**语义的场景——范围查询、找最接近的值、按序遍历、排行榜名次。
- **与哈希表对比**：哈希表查找更快（平均 O(1)）但无序；BST 查找 O(log n) 但天然支持范围/序遍历。二选一取决于"要不要顺序"。
- **实际落地**：数据库 B/B+ 树索引（BST 的多路推广，专为磁盘页设计）、`TreeMap`/`map`（红黑树）、Linux CFS 调度器、定时器的时间轮/有序表。

## 六、可继续学习的方向

- AVL 树与红黑树：旋转如何维持平衡（面试高频）。
- B 树 / B+ 树：为什么数据库索引不用二叉树。
- [堆](../堆/)：另一种"有序但只保证最值"的树——用更少的约束换更低的常数。
- LCA（最近公共祖先）、前驱/后继查询等 BST 上的经典操作。
